# IDR-023: v6 ratification — closure-gate verdict (EXTERNALLY VERIFIED WITH CONDITIONS) + operator ratification of the approved slices

**Status:** Decided — v6 ratified as the authoritative baseline (state ladder: RATIFIED for the approved slices)
**Date:** 2026-08-13
**Decides for:** The §27 item 43 standing condition ("v6 is not ratified until this gate passes") and the post-gate remediation that closed its conditions. This record is the ratification event: the operator accepts the v6 approved slices as the authoritative baseline for the next development phase.

## Context

v6's amendment package (ResearchProgram, IDR-018; ActionEvaluation, IDR-019; plus the Step-5 trust boundary and the P3 gateway/task-plan/walking-skeleton slice, IDR-021) sat at `IMPLEMENTED + TESTED` on the state ladder. §27 item 43 made the move to RATIFIED conditional on an **external independent closure gate** run by a verifier who did not touch the implementation — because the Part 6 review had been conducted by the same agent that implemented and remediated (independence disclosure, §3d).

## The gate (recorded here verbatim in outcome)

The independent verifier audited HEAD `979399e` with fresh runtime evidence only (no prior reports, no prior test counts trusted):

- **Baseline:** HEAD `979399e`, branch `main`, working tree clean, 108 tracked files, no junk/secrets.
- **Fresh suite:** `.venv/Scripts/python.exe scripts/run_tests.py -v` — **445 passed, 0 failed, 0 errors, exit 0, 7.15s**, Python 3.14.1 (exact match to the claimed count).
- **Authority-boundary audit (static + dynamic):** only `gateway.py` reaches repository write methods; `programs.py`/`evaluation.py`/`task_plan.py` are pure (no persistence imports). 71/71 independent dynamic checks passed (trust boundary A–I, gateway role table, INSERT_TASK attacks, evidence integrity, task-plan attacks, determinism incl. fresh interpreter, provenance in SQLite, atomicity injection, ActionEvaluation).
- **Step-5 trust boundary:** all nine forgery classes (forged COMPILED object, content_hash, program_id, input_hash, schema_version, obligations, and the Step-4 different-object-same-hash collision) fail closed with zero rows and zero `ResearchProgramCompiled` events; genuine duplicate idempotent.
- **Scope governance:** 10/10 fresh checks (valid/forged/changed/superseded/wrong-project/head-only).
- **No evidence-promotion path:** the only evidence table (`thesis_evidence`) has zero writers anywhere in src/tests; promotion payloads rejected at compilation; gate completion fabricates no scientific evidence.

**Verdict: EXTERNALLY VERIFIED WITH CONDITIONS.** No P0/P1 finding. Two P3 conditions:

| ID | Severity | Finding |
|---|---|---|
| V6-FINAL-01 | P3 | Task-admission constraint failures (missing dependency FK, idempotency-key reuse by a different task) surfaced as raw `sqlite3.IntegrityError` instead of structured `GatewayRejection` codes. |
| V6-FINAL-02 | P3 | INSERT_TASK `provenance` accepted unvalidated `research_program:<id>` references (false-lineage forgery vector). |

## Condition closure (IDR-022, HEAD 55ad4c4)

Both conditions were resolved and committed as one logical unit (`55ad4c4`, "v6 closure-gate remediation"):

- **V6-FINAL-01:** every `TaskRepository.create` failure now maps to a structured code — FK on a missing dependency → `DEPENDENCY` (naming the missing dep); `UNIQUE(idempotency_key, attempt)` reuse by a different task → new `IDEMPOTENCY_CONFLICT`; other integrity violations → `MALFORMED_PAYLOAD`. Never a raw `sqlite3.IntegrityError`. Same-task retry stays idempotent (PA4).
- **V6-FINAL-02:** two-tier provenance contract — the reserved `research_program:<id>` prefix must dereference to a program governed by the intent's project at admission (new `PROVENANCE` code; nonexistent/empty/cross-project references rejected); requirement-level annotations (`evidence_requirement:`/`hypothesis:`/`scope_brief:`) remain derived metadata, dereferenced by the future `provenance_edges` lineage layer.
- **Regression tests:** `tests/test_gateway.py` 26 → 30; walking skeleton corrected to admit the compiled program through the gateway before instantiating the plan (its documented flow).
- **Suite:** **449 passed, 0 failed, exit 0** at `55ad4c4`.

## Decision

**Ratify v6 as the authoritative baseline for the next development phase.** Concretely:

1. The v6 document (`hermes_research_architecture_v6.md`) moves to **RATIFIED** on the state ladder for the approved slices: P2 (ResearchProgram + ActionEvaluation), Step-5 trust boundary (EC-V6-11..16), and P3 (Intent Gateway + ResearchTaskPlan + walking skeleton).
2. HEAD `55ad4c4` is the ratified implementation baseline (parent `979399e` is the audited gate HEAD).
3. Ratification **does not** change the authority model, add capabilities, or authorize scope not already in the ratified text. §28.5 deferred rows (Director proposal variant P4, GR7 binding, program–spec binding, graph integration, scheduler/ADMIT_TASK runtime, budget ledger, optimizer Part 2, Research Observatory, Research Debt, Uncertainty Budget, skill registry, graph database, PA1/PA4/PA5/PA7/PA8 mechanisms beyond v5.1) remain DEFERRED and are not ratified.
4. Future phases build on this baseline; any future amendment to the ratified slices follows the same five-stage loop and, where it changes normative rules, requires its own decision record.

## Rationale

1. **The gate's purpose was served.** §27 item 43 exists to ensure the next development phase does not carry forward a hidden architectural defect. The independent audit found no P0/P1 defect, re-verified every authority boundary and the Step-5 trust boundary with fresh evidence, and its two P3 conditions are now closed with committed regression tests. Continuing development on this baseline does not carry hidden architecture debt.
2. **Ratification is the operator's call, exercised here.** The gate certifies trustworthiness; the operator decides to adopt. This record separates the two: the gate's verdict is recorded above, the ratification decision is this record's subject.
3. **Scope discipline preserved.** Ratification is of the approved slices, not of everything §28 describes. Deferred rows stay deferred — this record does not silently convert future-looking text into authorized scope.

# IDR-020: `ix smells` orphan-file findings are true positives — unwired/deferred modules, not a map defect

**Status:** Verified + documented (no code or map change)
**Date:** 2026-08-13
**Decides for:** Whether the 60 "orphan file" candidates reported by `ix smells` (graph rev 22) on this repository are a graph-coverage defect or genuine architectural signal, and what the v6 ratification gate should do with them.

## Context

`ix smells` (Ix 0.9.3, rev 22) reported 73 candidates on this repository: **60 Orphan File (connections=0)**, 12 God Module, 1 Weak Component. The orphan list includes core-named modules — `director.py`, `gateway.py`, `reconcile.py`, `evidence.py`, `provenance.py`, `gates.py`, `integrity_gates.py`, `adversary.py`, `implementer.py`, `researcher.py`, `sandbox.py`, `execution.py`, `heartbeat.py`, `leases.py`, `changes.py`, `ci.py`, `worktrees.py`, `research_sources.py`, `reporting.py`, `models.py`, `boundaries.py`, `registration.py`, `projection.py` — plus docs, config, `__init__.py`, `conftest.py`.

Because `ix trace`/`ix rank`/`ix explain` resolve cross-file references for other symbols, the finding was initially (and wrongly) characterized in-session as a "graph-coverage artifact." That inference was unsound: every symbol traced during verification (ResearchProgram, ActionEvaluation, ProjectRepository, evaluate_candidates) belongs to the *wired* minority of the codebase.

## Method / verification

1. **Source-truth grep.** All 24 named source modules have **zero importer-references** across `src/` and `tests/` (reference-pattern grep excluding self-matches). The only out-of-module "director" hits are a docstring (`core/intents.py:56`) and a string default (`persistence/repositories.py:856`) — neither is an import.
2. **Graph cross-check.** `ix trace director.py` → Upstream (none), Downstream (none), 0 nodes visited. `ix trace ProjectRepository` (rank: 51 dependents) → rich upstream caller tree. The metric discriminates correctly; the graph is not blind to cross-file edges — imports such as `from hermes.research.programs import CompilationStatus` (`repositories.py:41`) and `from hermes.core import utc_now, Clock` resolve and trace normally.
3. **Import census.** The wired set is: `cli.py`; `persistence/*` (database, migrations, repositories, backup, event_validation); `core/` (node, graph, task_status, lifecycle, modes, events, intents); `artifacts/store`; and the Epistemic-Compiler slices — `research/programs.py` (imported by `repositories.py` and `evaluation.py`) and `research/evaluation.py` (imported by its own tests only; Director integration deferred per v6 §28).

## Decision

**No map fix is warranted. The orphan-file smell is a true positive for source modules: they are landed-but-unwired components whose operational integration is deferred — the same pattern as the EC slices, whose own downstream traces are "(none)".** The remaining orphan candidates (README, IDR-001…019, architecture v3/v4/v6 docs, `pyproject.toml`, `hermes.toml`, `__init__.py`, `conftest.py`) are connection-less by nature — docs/config/package markers have no import edges, and `conftest.py` fixtures are resolved by pytest by name.

## Rationale

1. **Graph health.** 97 files, 2,004 nodes, 4,951 edges (map rev 21/22); trace/rank/explain/smells all agree with source grep on every probe.
2. **Architecture consistency.** v6 §28 records ResearchProgram gateway wiring (P3) and ActionEvaluation Director integration (P4) as deferred; the "(none)" downstreams confirm the code has not drifted ahead of the ratified slices. The broader orphan set extends this pattern: the v5.1 role-profile agents (Director/Adversary/Implementer/Researcher), Intent Gateway, evidence/provenance/gates, reconcile, sandbox, execution, recovery heartbeat/leases, and engineering changes/ci/worktrees are present as modules but are not imported by any runtime path in the current phase-1 implementation.
3. **Correction.** The in-session "graph-coverage artifact" characterization was wrong and is hereby retracted. The graph's only genuine coverage limitations: (a) file-level "connections" naturally exclude name-based references (pytest fixtures in `conftest.py`, CLI entry-point discovery, SQL text in migrations), and (b) docs/config have no import edges by nature.

## Consequences

- **No code or map change.** The `ix smells` output stands; re-running on the same graph yields the same candidates (deterministic, inference_version=smell_v1).
- **Evidence for the v6 ratification gate.** The orphan list is a machine-derived inventory of unwired modules. The external independent closure reviewer (v6 §27 item 43) should use it to (a) confirm each listed module's unwired status is the ratified deferral (P3/P4/P6+), not an accidental omission, and (b) confirm nothing claimed wired in §28.6 is absent from the wired set.
- **Follow-up candidates (not implemented here).** Distinguishing "deferred-by-design" from "forgotten" orphans is a judgment for the §27 item 43 review; optionally, per-run `ix smells --list` snapshots could be archived alongside the report archive convention.

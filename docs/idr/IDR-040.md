# IDR-040: Q-04 artifact-layer blast radius + re-review candidates +
# SOURCE_RETRACTED trigger as Hermes architecture

**Status:** IMPLEMENTED + TESTED — **RATIFIED / CLOSED (2026-08-15)**: the
Q-04 §5 extension AND the Q-05 §3 proposal lifecycle are adopted as
**Hermes architecture** — the artifact-layer forward reachability over the
ratified `provenance_edges` edge set, the dispatch-blocked diagnostic note
(Q-04 §3.4), the re-review candidate surface (blast radius ∩ outstanding
Q-05 classifications), the ratified `SourceRetracted` event as its seed
trigger, and the human-approval gate on classification-action proposals (the
gate state, the ratified decision, the pending-proposals replay, and the
operator-verdict ingestion surface). Everything is pure, derived,
deterministic, recomputed-per-query, and read-only except the two
append-only audit RECORDS (the retraction record and the decision record —
no authority is added by either). Adversarial audits found and fixed one
defect each (F10 — the dispatch note claimed SUCCEEDED cone members were
blocked, `cf88053`; F11 — the replay and the decision gate trusted the
stored proposal state instead of recomputing the gate from the
classification's class (F2), `d960ba3`). Reviewer provenance: the audits
were executed by the implementation agent at operator instruction —
ratification is by operator authority; INDEPENDENTLY VERIFIED by an
external party is not claimed.

## Context

IDR-039 ratified the task-layer traversal and explicitly deferred
artifact-level edges to the lineage phase. This IDR extends the SAME
contracts to the artifact layer without waiting: `provenance_edges` already
carries five ratified edge types (`cites`, `derived_from`, `supersedes`,
`used_as_input`, `justifies`) with no schema change, so a retracted or
superseded SOURCE artifact can already surface every downstream artifact
that cites or derives from it — transitively. The re-review candidate set
is the intersection of that blast radius with OUTSTANDING Q-05
classifications: the Director sees exactly the downstream artifacts that
carry a recorded classification, each with its D3
`failure_classification:<hash>` ref. The seed trigger is the ratified
`SourceRetracted` catalog event (ADV-05 — a declared enum member that had
no emit path); recording it is an append-only AUDIT (nothing is retracted,
invalidated, or modified), and the advisory reads it as the seed source.

## 1. The contract (versioned, derived, read-only)

**Sources of truth (all ratified; nothing stored is derived — F2):**

| Fact | Ratified source | Read authority |
|---|---|---|
| artifact lineage (downstream edge) | `provenance_edges` (insert-only, UNIQUE) | read-only SELECT, project-scoped on the downstream artifact |
| artifact identity/type | `artifacts` (append-only) | read-only SELECT |
| outstanding classification | Q-05 `classifications_digest` (unflagged items only) | read-only digest |
| retraction seed | `events` rows of type `SourceRetracted` (append-only) | read-only SELECT |

**The pure functions** (`core/graph.py`, no SQL, no writes — the AC-7
authority scan is fixture-pinned):

- `artifact_blast_radius(seeds, downstream)` — the transitive downstream
  closure over `provenance_edges`, each reached artifact labeled with the
  ROOT seed (first-ancestor convention, matching `failure_cone`) and the
  edge type of first visit. Deterministic (sorted seeds/edges,
  first-visit-wins, visited set — hand-inserted 2-cycles terminate), seeds
  are never results, unknown seeds are empty. The artifact analog of
  `change_blast_radius`: reachability REGARDLESS of status — the lineage is
  the fact; review need does not depend on a downstream status.
- `re_review_candidates(blast, classifications_by_artifact)` — the
  intersection with OUTSTANDING classifications: a downstream artifact is a
  candidate iff at least one D8-valid, unflagged digest item cites it
  (edge type `cites`, upstream = the evidence artifact). Carries the
  classification refs, failure classes, and the aggregated
  `requires_human_confirmation`. Never invents a ref for a corrupt row.

**The dispatch note (Q-04 §3.4):** when a dispatch pass finds no eligible
tasks and the idle is caused by a failure cone whose blocking ancestor
carries a Q-05 classification, the controller records a diagnostic note on
the notes channel (`Q-04: dispatch blocked by failure cone of task A
(FAILED — <class>); blocked dependents: ...`). Diagnostic ONLY — the
eligibility logic, the recovery ladder, and the dependency gate are
untouched. One note per classified ancestor, deterministic order, only
when `tasks == []`, never when eligible work exists (a RETRYING root is
itself eligible, so the note only fires when the classified FAILED root
blocks everything downstream of it).

## 2. Authority boundary

- **CAN** surface the re-review candidate set (names what needs re-review,
  with the blocking edge, the failure label, and the classification refs).
- **CAN** RECORD a retraction FACT: `record_source_retraction` appends a
  `SourceRetracted` event bound to the artifact — validated at admission
  (the artifact exists in the project AND is a source-type artifact:
  `source_result` / `source_payload` / `source_search`; anything else is
  refused with `SourceRetractionError` and nothing is written). Append-only:
  no task transitions, no artifact mutation, no event UPDATE/DELETE.
- **CANNOT** retract, invalidate, supersede, auto-fail, or modify anything
  — the retraction authority stays where it already lives (framework §G).
  The record is the OBSERVATION; the advisory is the CONSEQUENCE VIEW.
- **CANNOT** decide scheduling: `_discover_eligible`, the dependency gate,
  and IDR-029's ladder are untouched.
- **CANNOT** write from the advisory surfaces: `artifact_blast_radius`,
  `re_review_candidates`, and `retracted_source_review_candidates` are
  pure reads (fixture-pinned no-write); `_cone_blocked_dispatch_notes`
  writes only to the notes channel.
- **CAN** RECORD the ratified operator verdict: `record_operator_decision`
  admits a `RESOLVE_CLASSIFICATION_PROPOSAL` intent (DETERMINISTIC — the
  human has no agent profile) through the gateway, appending the
  append-only `ClassificationActionDecision` event (one proposal, one
  verdict; idempotent repeats; contradictory verdicts refused). The write
  is LEASE-HELD (the scheduler lock is acquired for the verdict's
  duration — a concurrent controller's lease refuses the verdict
  fail-closed with code `LOCK`, and the lease is released after).
- **CANNOT** decide or execute anything: a pending proposal is only the
  gate state; the ACTION still requires its existing authority (ABANDON /
  EVIDENCE_TRANSITION / PROPOSE_RESEARCH_PROGRAM / S16). The gate, the
  replay, and the decision validator all RECOMPUTE
  `requires_human_confirmation_for` from the classification's class (F2) —
  never from the stored admission state, so a tampered state can neither
  fabricate a pending advisory nor block a genuine decision.

## 3. Controller integration (read-only consumption + one audit record)

- `Controller.artifact_blast_radius(seeds)` — project-scoped read of
  `provenance_edges` (scoped on the DOWNSTREAM artifact's project — the
  review obligation lives in the citing project), fed through the pure
  traversal, returned version-bound + hashed (`GRAPH_QUERY_VERSION="1"`,
  kind `artifact_blast_radius`).
- `Controller.re_review_candidates(seeds)` — the same radius joined with
  `classification_proposals()` (the ratified digest): only UNFLAGGED items
  are "outstanding"; a forged/corrupt classification row is dropped by the
  digest and can never become a false candidate.
- `Controller.record_source_retraction(artifact_id, caused_by, reason)` —
  the Director-side write: validated, append-only `SourceRetracted` event
  (ratified v4 §8.1 catalog member, boundary-validated). Inside a tick the
  append is fenced (lease-attributed); a Director-side record outside a
  tick appends directly — an append-only audit event touches no state
  machine, so the unfenced append carries no lease-race hazard.
- AUTO-EMIT (execution-driven): `SourceOutcomeRepository._commit` now emits
  the same `SourceRetracted` event in the SAME transaction whenever a
  fetch outcome RECORDS a `REMOVED_OR_RETRACTED` no-full-text hazard
  (HZ-02 — the kind is derived only from a provider-declared retraction
  marker, never bare presence), bound to the source's ratified
  `source_result:<hash>` ref, `NEW` decision only (IDENTICAL reuse
  re-delivers an already-committed outcome whose event was emitted at first
  commit; DIVERGENT is refused before commit — the record and the event
  commit or fail together). NOT_OA is never a retraction. The advisory
  resolves the ref-form seed by content hash (SD-05) so the event's
  artifact identity round-trips to the `art_<hash>` artifact row.
- `Controller.retracted_source_review_candidates()` — seeds the candidate
  surface from the RECORDED `SourceRetracted` events (project-scoped).
  Fail-closed: a corrupt `artifact_ids_json`, a ref-form seed with a
  wrong-type prefix, or an artifact no longer resolvable in the project is
  skipped with an observable note — never a crash, never a silent seed,
  never a cross-project seed (deduped via `sorted(set(...))`).
- `Controller.reconcile_digest()` — the Director's daily one-call surface:
  the Q-05 classification proposals + the re-review candidates folded into
  a version-bound (`RECONCILE_DIGEST_VERSION="1"`), content-hashed
  composite. Never writes, never executes, never retracts — everything the
  Director needs to ACT is here, and nothing here can act.
- `Controller.propose_review_actions()` — the DIRECTOR ACTION LOOP: consumes
  `reconcile_digest()` and emits each candidate's permitted actions as
  `PROPOSE_CLASSIFICATION_ACTION` intents THROUGH the gateway (the single
  mutation boundary). The new intent kind (Director-only, not
  LLM-proposable) admits the proposal as a ratified
  `ClassificationActionProposed` audit event — the audit IS the record; the
  ACTION is never executed here and still requires its existing authority
  (ABANDON / EVIDENCE_TRANSITION / PROPOSE_RESEARCH_PROGRAM / S16).
  Validated at admission: D3-dereference of the classification ref,
  ratified `PermittedAction` member, candidate artifact existence,
  Director-only role; idempotent via a deterministic proposal id — repeat
  digest runs duplicate nothing. This is the ONE authority addition in the
  extension, and it is proposal-shaped, not execution-shaped.
- THE HUMAN-APPROVAL GATE (§3.5): a `PROPOSE_CLASSIFICATION_ACTION`
  proposal is admitted with a gate state derived at admission from the
  dereferenced classification's class via `requires_human_confirmation_for`
  (the ONE class that requires confirmation is FRAMING_ERROR): such a
  proposal is admitted `PENDING_HUMAN_APPROVAL` and can NEVER become
  executable until a ratified decision; every other class is admitted
  `EFFECTIVE` and needs no decision. The gate is recomputed, never trusted
  from storage — a tampered non-ratified `failure_class` is refused at
  admission.
- THE RATIFIED DECISION: the new internal-only intent kind
  `RESOLVE_CLASSIFICATION_PROPOSAL` (DETERMINISTIC — the human has no agent
  profile; the deterministic layer ingests the operator verdict) is
  validated at admission (the proposal exists AND is decidable — its class
  REQUIRES human confirmation, recomputed (F2); the decision is a ratified
  APPROVED / REJECTED; unknown payload keys rejected) and appends the
  append-only `ClassificationActionDecision` event
  (`correlation_id = proposal_id`). ONE PROPOSAL, ONE VERDICT: an
  identical re-record is idempotent (`duplicate=True`); a contradictory
  second verdict is refused and nothing is written.
- THE PENDING-PROPOSALS REPLAY (the propose-observe loop): the reconcile
  loop replays every undecided proposal whose class requires human
  confirmation into the Director's next digest run —
  `Controller.pending_classification_proposals()` (deterministic
  `event_id` order) folded into `reconcile_digest` v2 (`pending_proposals`
  section, `RECONCILE_DIGEST_VERSION="2"`, content-hash bound — deciding a
  proposal changes the digest identity and drops it from the next run).
  Fail-closed: a corrupt payload, an undereferenceable classification, or
  a class that does not require confirmation is skipped with an observable
  note (a stored state that contradicts the recomputed gate is a TAMPER
  SIGNAL — noted, and the class wins).
- THE OPERATOR-VERDICT INGESTION SURFACE: `Controller.record_operator_decision`
  is the FIRST-CLASS sanctioned path for the human verdict — it builds the
  `RESOLVE_CLASSIFICATION_PROPOSAL` intent and admits it through the
  gateway. The write is LEASE-HELD (the scheduler lock is acquired for the
  verdict's duration; a concurrent controller's lease refuses the verdict
  fail-closed with code `LOCK` and nothing is written; the lease is
  released after, never left behind). Rejections are surfaced as data,
  never raised through the loop.

## 4. Deferred (explicitly NOT ratified here)

- New artifact-level edge types (`conflicts_with`, `introduces_risk`) still
  require a schema change and LLM-proposed edge existence — still deferred
  to the provenance-lineage phase.
- An automatic retraction ladder (record → auto-retract downstream) is
  explicitly NOT architecture: the record is an audit fact, the advisory is
  a view, and the Director retains the only retraction/supersede authority.

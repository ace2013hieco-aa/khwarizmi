## Context

Part 1 reviewed the CONTRA research-vault design against the ratified v6 baseline and found that the source's headline capability (internal contradiction detection) already exists in v6 (§19 + GR3 + GR6 + `ContradictionDetected` + `CONTRADICTION_RESOLUTION` + UNCERTAIN semantics). Three genuine gaps survived the protest: (1) a first-class `ResearchAssumption`, (2) the context-vs-contradiction distinction, (3) steelman as a structured Adversary mode. Part 1 proposed an amendment package: `ResearchClaim` + `ResearchAssumption` artifacts (P7), contradiction contextualization routing (§19, P11), the steelman mode (§13, P11), a `/contra/` renderer projection (§21), a manual-proof-first rule, and deferred ghost-self/cross-domain.

## Reconciliation method

Part 2 re-attacks Part 1's own proposals before deciding — the second pass must not rubber-stamp the first. Each surviving proposal was checked against four questions:

1. Does it create a new authority, scheduler, memory system, or evidence engine?
2. Does it duplicate an existing concept under a new name?
3. Could it *hide* a real finding (false negatives are the failure mode of a contradiction system, not just false positives)?
4. Does it respect the ratified invariants (single mutation path, §21 single vault writer, §10.2 ladder ownership, "never evidence" rules)?

## Reconciliation findings (corrections to Part 1)

**CT-R1 — Part 1's context-below-floor *suppression* is wrong; the context gate classifies, it never suppresses.** Part 1's §17 said a context-tag overlap below the floor "suppresses the challenge entirely as noise." That is a false-negative risk: two conflicting claims with non-overlapping tags may simply lack context data, and suppressing them hides a real contradiction — exactly what §19 and the source's own governance principle forbid ("surface, never hide"). **Correction:** the context gate is a *routing classifier*, not a filter. Equivalent context + conflicting content → direct-contradiction path (UNCERTAIN). Differing context → `ResearchChallenge` type CONTEXTUALIZED (advisory, surfaced, no evidence effect). **Missing/UNKNOWN context defaults to the direct-contradiction candidate path** — fail-open toward surfacing. Suppression is reserved for the explicit controls only: content-derived duplicate suppression, stale/out-of-scope targets, source-quality screening, and an operator-configured severity floor (which surfaces nothing, it only changes what reaches the Director vs. the digest).

**CT-R2 — `ResearchClaim` has no ladder surface and relates to the §10.2 `Claim` by citation only.** The existing `Claim`/`EvidenceRecord` (§10.2, E2) is the governed, citable-class link. `ResearchClaim` is the extraction-level atomic assertion. The two must never conflate: a governed claim may *cite* corpus claims it rests on; a `ResearchClaim` can never be a `Validation`, a ladder precondition, or an `EvidenceRecord` (the "never evidence" rule, PA2/GR3, applies verbatim — made a structural test).

**CT-R3 — corpus assumptions can never bear obligations.** An `ResearchAssumption` may flag (ASSUMPTION_FLAG challenge), but it cannot add, remove, or alter any governed obligation. A `ResearchProgram`'s obligations are derived by `ResearchProgramValidator` alone (E1–E5, EC-V6-14); an `ExperimentSpec`'s design is governed by its own validator. Corpus assumptions are advisory premises; the dependency direction is one-way (governed objects may reference assumption ids; assumptions never constrain governed objects). Otherwise assumptions would become a second planning authority.

**CT-R4 — challenge status transitions are human/Director-driven except one deterministic case.** `SUPERSEDED` (target claim version superseded) is deterministic and version-aware — a bookkeeping transition, not a truth statement. Every other status (`OPEN → INVESTIGATED → CONTEXTUALIZED / UNRESOLVED / RESOLVED_BY_EVIDENCE`) is set by a human decision or a Director-proposed, gateway-admitted action. In particular **`RESOLVED_BY_EVIDENCE` is settable only by the evidence machinery itself** (a subsequent `Validation`/experiment through the §10.2 path) — a challenge can never mark itself resolved.

## Normative rules entering v6 (amendment package summary; full template text in `hermes_contra_adversarial_review.md` §20)

1. **Advisory substrate rule.** `ResearchClaim`/`ResearchAssumption` are project-scoped, immutable, supersession-edged §16 artifacts. Neither is ever a `Validation`, ladder-citable, or a gate input. A governed claim may cite corpus claims; corpus claims may not enter the ladder path.
2. **One-directional dependency rule.** Assumptions live once in the corpus layer. Governed objects (ResearchProgram, ExperimentSpec) may reference assumption ids; assumptions never add/remove/alter obligations (validator-derived obligations unchanged, EC-V6-14).
3. **Routing-not-suppression rule (§19).** Candidate conflicts are classified deterministically on structured context tags: equivalent context → existing §19/UNCERTAIN path; differing context → CONTEXTUALIZED advisory challenge (no UNCERTAIN, no evidence effect); unknown context → default to the contradiction candidate path (fail-open). Method/data/interpretation/temporal conflicts route to existing deterministic checks and the human/Director path per the Part 1 taxonomy table. Suppression is limited to dedup/stale/out-of-scope/source-quality controls.
4. **Challenge authority limit.** A `ResearchChallenge` surfaces, compares, challenges, steelmans, and requests investigation. It cannot promote/refute evidence, invalidate a hypothesis, approve/fail a gate, or set its own terminal status (CT-R4).
5. **Closed-provenance steelman rule.** A steelman without dereferenceable source-artifact refs is rejected by the validator (the GR9/IDR-022 dereference discipline).
6. **Projection rule.** `/contra/CH-xxx.md` is regenerated from authoritative state on every render; no edit-back path; no renderer intent path (§18 T1); human decisions flow through the governed inbox/intent mechanism only.
7. **Manual-proof-first rule.** The P7 substrate and P11 steelman/contextualization ship golden fixtures (assertion-correctness, the S8 pattern) and pass adversarial review before any scheduled execution.
8. **Zero new authority/scheduler/event/intent.** All triggers end at the existing Reconcile loop (responsibility 8), PA5 scheduled re-entries, or `apply_intent`.

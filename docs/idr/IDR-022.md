# IDR-022: Closure-gate remediation — structured task-admission rejections (V6-FINAL-01) and the INSERT_TASK provenance contract (V6-FINAL-02)

**Status:** Decided + implemented + tested (post-closure-gate remediation, v6 §27 item 43 conditions)
**Date:** 2026-08-13
**Decides for:** The two P3 conditions attached to the v6 external closure-gate verdict (`EXTERNALLY VERIFIED WITH CONDITIONS`, HEAD 979399e): the gateway must surface every task-admission constraint failure as a structured `GatewayRejection` code, and the INSERT_TASK provenance field needs a decided dereference contract.

## Context

The final independent closure gate (v6 §27 item 43) audited HEAD `979399e` and found no P0/P1 defects. Two P3 findings were recorded as non-blocking conditions:

- **V6-FINAL-01:** `INSERT_TASK`/`ADMIT_TASK` admission surfaced some repository-level constraint failures as raw `sqlite3.IntegrityError` instead of structured `GatewayRejection` codes. Specifically: a missing dependency violated the `task_dependencies` FK (raw `IntegrityError` — the `DEPENDENCY` code covered only the self-cycle path), and reusing `UNIQUE(idempotency_key, attempt)` for a *different* task_id raised a raw `IntegrityError`. Rejection, audit event, and no-half-state all held; only the caller-facing error surface was unstructured.
- **V6-FINAL-02:** `provenance` on INSERT_TASK was unvalidated caller-supplied metadata — any admitted agent could attach `research_program:<id>` references to programs that do not exist (false-lineage forgery). The plan-generated provenance is truthful by construction, but arbitrary task admission had no dereference check.

## Decision

**V6-FINAL-01 — every task-admission constraint failure gets a structured code. The `DEPENDENCY` rejection is broadened; a new `IDEMPOTENCY_CONFLICT` code is added; everything else stays `MALFORMED_PAYLOAD`.** In `_validate_insert_task` (gateway.py), `TaskRepository.create` failures are classified:

- `DependencyError` (self-cycle) → `DEPENDENCY` (unchanged).
- `sqlite3.IntegrityError` with `FOREIGN KEY` (missing dependency) → `DEPENDENCY`, naming the first missing dependency. A missing dependency is a DAG violation, not a payload-shape error — it belongs to the existing code.
- `sqlite3.IntegrityError` with `idempotency_key` (`UNIQUE(idempotency_key, attempt)` collision) → **new code `IDEMPOTENCY_CONFLICT`**. PA4 semantics: an idempotency key identifies one command; a *retry* of the same task (same task_id + same key) stays idempotent, but the *same key claimed by a different task* is a conflicting command and must fail loudly — never silently accept, never a raw error.
- Any other `sqlite3.IntegrityError` → `MALFORMED_PAYLOAD` (fail-closed catch-all; CHECK/PK violations should be unreachable through the validated payload).

The audit-event guarantee is unchanged: every rejection — structured or not — already appends `IntentRejected` (the gateway's generic except path), so this change only upgrades the error surface, never the audit trail.

**V6-FINAL-02 — two-tier provenance contract at INSERT_TASK/ADMIT_TASK admission.** `provenance_json` remains **non-authoritative metadata** in P3 (the authoritative lineage mechanism is the `provenance_edges` table, populated by a future phase). Within that, one reference class is enforced now:

- **Tier 1 — enforced (new `PROVENANCE` code):** any entry with the reserved prefix `research_program:<id>` must dereference — a program with that `program_id` must be recorded for the intent's *project* at admission. Rationale: this is the only reference class that is (a) unambiguously dereferenceable at the payload level, (b) produced by the task plan for every plan task, and (c) the concrete forgery vector the audit found (claiming lineage to a nonexistent program). Programs are immutable and never deleted in this tree, so enforcement cannot break legitimate plan replays.
- **Tier 2 — documented, not enforced:** `evidence_requirement:<ref>`, `hypothesis:<ref>`, `scope_brief:<ref>` and any other entries are derivation annotations. They are truthful-by-construction when generated by `task_plan.py` and their authoritative dereference is tied to the program's own requirement set — that check lands with the lineage layer (P4+), not here.

Explicitly **not** decided: populating `provenance_edges`, making provenance authoritative, or validating requirement-level refs at admission — those belong to the deferred lineage phase.

## Rationale

1. **Structured errors are the gateway's contract.** v6 §28.5 describes the gateway by its stable rejection codes; a raw `sqlite3.IntegrityError` escaping that surface is a contract leak even when the invariant (no bad task admitted) holds. The fix is classification at the single choke point — no repository changes, no new write path.
2. **The provenance rule is the minimum enforceable truth.** Partial enforcement was chosen deliberately over both extremes: full dereference of every prefix is not well-defined in P3 (`hypothesis:H1` is meaningless without program context), and zero enforcement leaves the concrete false-lineage attack open. Enforcing the one prefix that is *unambiguously* dereferenceable closes the attack at zero architectural cost and is satisfied by every plan-generated task.
3. **No authority movement.** The gateway still cannot validate program semantics, re-derive identity, promote evidence, or spend budget. The two new codes and the provenance check are admission-surface hardening, not new authority.

## Consequences

- **Implemented + tested.** Gateway now classifies FK/idempotency/integrity failures as `DEPENDENCY` / `IDEMPOTENCY_CONFLICT` / `MALFORMED_PAYLOAD`; `_validate_provenance` enforces the `research_program:` dereference rule. Walking skeleton corrected to actually admit the compiled program through the gateway before instantiating the plan (its docstring already claimed this; the missing admission step was exposed by the new dereference check).
- **Regression tests (4 new, `tests/test_gateway.py` 26 → 30):** missing dependency → structured `DEPENDENCY` (audited, no half-state); idempotency-key reuse across different tasks → `IDEMPOTENCY_CONFLICT` while same-task retry stays idempotent; `research_program:` nonexistent / empty / other-project → `PROVENANCE`; valid governed program → accepted. `test_v6_attacks.py` idempotency test updated to a non-reserved provenance ref.
- **Suite:** **449 passed, 0 failed, exit 0** (was 445). v6 §28.5 updated (codes list, provenance contract, counts). v6 remains `IMPLEMENTED + TESTED` — this remediation is not a ratification event.

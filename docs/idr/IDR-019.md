# IDR-019: Research Process Optimizer — ADOPT AS A DETERMINISTIC EVALUATION LIBRARY

**Status:** Decided + implemented (P2 slice; Part 2 reconciliation deferred)
**Date:** 2026-08-12
**Decides for:** Whether Hermes adopts a "Research Process Optimizer" and, if so, in what form. Records the Part 1 protest verdict and the implemented residue.

## Context

An external proposal asked Hermes to adopt a "Research Process Optimizer" — a component that "selects the next governed research action" by balancing expected uncertainty reduction, research value, cost, time, risk, existing evidence, competing hypotheses, research debt, frontier opportunities, methodology suitability, and available resources. The proposal was reviewed in one part (Part 1 — architectural protest, necessity review & design exploration):

- The proposal's own pipeline ("optimizer → ranked candidate actions → Director") is defensible **only if** the optimizer *ranks* and the Director *decides*. Any design in which the optimizer's output has selection weight, auto-dispatch, or a "worth doing" verdict creates **two planners** — the exact failure class the Epistemic Compiler protest (IDR-018) rejected. "Decide what research is worth doing" is the Director's standing responsibility (v5.1 §13: holistic judgment, sole standing to propose state changes).
- "Optimize" is undefined in the proposal, and a weighted objective is not defensible: v5.1 has no calibrated posterior model from which "expected uncertainty reduction" can be computed, and a `research_score = 0.87` would be false precision that Goodhart-targets itself (S2's lesson: reporting attribute, never a precondition).
- The optimizer must **not invent actions** — S3 gap tasks, GR6 graph-computed gaps, and S14 freshness proposals already generate the candidate set; a component that generates its own tasks is a second scheduler.
- What survives the protest is real but narrow: Hermes receives heterogeneous, ad hoc advisory signals (S3 gap lists, S2 corroboration dispatch, GR6 graph gaps, GR8 diagnostics, S14 freshness proposals) with **no uniform, reproducible, structurally-explainable comparison of admissible next actions** — no way to answer "why action A rather than B" except Director prose. That auditability gap is the same class the ResearchProgram closed for "why does this task exist."

## Decision

**The optimizer-as-authority is rejected. The ActionEvaluation deterministic evaluation library is adopted (ADOPT AS A DETERMINISTIC EVALUATION LIBRARY).** The P2 slice is implemented:

1. **Library — `hermes/research/evaluation.py`.** Pure, deterministic, stdlib-only (no SQL, no persistence, no LLM, no clock, no random). `CandidateAction` (an EXISTING admissible action only — never invented), `ActionEvaluation` (one candidate's full comparison record), `CandidateRanking` (the hashed, versioned advisory artifact), `RankingDiagnostic`.
2. **No scalar score, no weighted utility.** The ordering is a documented, versioned **lexicographic policy** over named dimensions (`evidence_gap_closure, contradiction_reduction, rival_discrimination, replication_value, frontier_value, coverage`), with cost/time/compute tier tiebreaks (`LOW|MEDIUM|HIGH|UNKNOWN`; `UNKNOWN` sorts last and is never treated as a value) and a `candidate_ref` deterministic tie-break. The full comparison table and the ordering policy are embedded in the ranking so the Director can see exactly why one candidate precedes another.
3. **Determinism and identity.** Same candidate set + same state facts + same version triple (`evaluator_version`/`policy_version`/`schema_version`) ⇒ identical `content_hash`/`ranking_id = "eval_" + content_hash[:24]`, across processes and input orderings (candidate order, selection-history order, stale-id order are all canonicalized). AC-01/AC-12.
4. **Gates dominate.** `blocked_by` ⇒ `EXCLUDED_GATE` — never ranked (AC-03), even for the highest-value candidate. Unsatisfied dependencies ⇒ `BLOCKED_DEPENDENCY`, surfaced for engineering-plane routing.
5. **Failures surfaced, never hidden.** `STARVED_CANDIDATE` (proposed across rounds, never selected — surfaced, never auto-promoted), `STALE_INPUT` (flagged per-candidate and as a diagnostic), `EMPTY_CANDIDATE_SET` (never a synthetic candidate), `NO_IMPROVEMENT` (policy: stop/pause/human — never pass).
6. **No authority surface.** Structural tests assert the module contains no repository/persistence/SQL/budget/spend/evidence-promotion vocabulary. `CandidateRanking` is a transient projection (like `GraphDiagnostics`), re-derivable on demand, never persisted as evidence, never a gate input.
7. **Tests — `tests/test_evaluation.py` (31 tests).** AC-01..12 of the Part 1 §33 list mapped to the library contract, plus determinism invariants (ordering invariance, cross-process reproducibility), gate dominance, UNKNOWN-tier handling, staleness/starvation diagnostics, and the no-scalar-score invariant.

## Rationale

1. **One planner, one selector.** Selection judgment stays with the Director; the library compares and explains. "The Optimizer decides what the Director should do" is exactly the unnecessary extra layer the protest rejected.
2. **Auditability without authority.** The gap is that prioritization is currently un-inspectable prose. The `CandidateRanking` makes the tradeoff between epistemic progress, evidence needs, uncertainty, cost, risk, and time explicit and auditable — without surrendering judgment to a score.
3. **Nothing to maximize ⇒ nothing to Goodhart.** The multidimensional lexicographic comparison has no target function to game; a scalar weighted score would. This is the anti-gaming position taken structurally, not by policy.
4. **Determinism is the reproducibility contract.** Identical inputs and versions must yield an identical ranking — the same discipline the ResearchProgram hash (IDR-018) applies, so recommendations are independently reproducible (AC-12).
5. **Phase honesty.** The P2 slice is the pure evaluation library. Not implemented: candidate-set sourcing integration (S3/GR6/S14/ResearchProgram obligations as `CandidateAction`s), Director/round integration, cost-model calibration, human-oversight surface — all deferred to a Part 2 reconciliation (v6 §27 item 47).

## Consequences

- **Implemented:** the P2 slice above. Full suite: 374 passed (31 new, Python 3.14.1); v6 focused suites green.
- **Authority boundaries:** the library CAN rank and explain existing admissible candidates with deterministic, versioned, content-addressed output; it CANNOT create or mutate tasks, lifecycle, evidence, gates, budgets, provenance, or graph state; cannot bypass the Director or the Intent Gateway; cannot promote evidence; cannot spend resources; cannot auto-dispatch; cannot invent actions.
- **Deferred (explicitly not implemented):** Part 2 reconciliation (candidate sources, cost model, human-oversight surface — v6 §27 item 47); Director/round integration (P3); any embedding/GraphRAG ranking feature (GR4 path-based first, GX5 opt-in port — the evaluator stays the sanctioned ranking mechanism); Research Observatory / Uncertainty Budget / Research Debt integration.
- **Anti-gaming posture:** no scalar score exists; weights, if ever wanted, are a `policy_version` parameter at most — advisory, never a gate; starved candidates are surfaced, never auto-promoted.

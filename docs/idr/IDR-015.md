# IDR-015: Concurrency Strategy — WAL + busy_timeout + Advisory Lock

**Status:** Decided (Phase 1)
**Date:** 2026-08-10
**Decides for:** How local concurrent access is handled.

## Context

Phase 1 req §17: test local concurrent access (two writers, same task
transition, different tasks, lock contention). v3 §8: single-writer discipline
via a SQLite advisory lock. v3 §16.4: WAL mode. The system must fail
deterministically rather than silently corrupting state.

## Decision

### WAL mode
- `PRAGMA journal_mode=WAL` on every connection.
- WAL allows concurrent readers with a single writer.
- Readers see a consistent snapshot; the writer serializes.

### busy_timeout
- `PRAGMA busy_timeout=5000` (5 seconds) — a writer that gets
  `SQLITE_BUSY` waits up to 5s before raising.
- This handles brief lock contention without complex retry logic.
- After 5s, the caller gets `sqlite3.OperationalError("database is locked")`
  — a deterministic, non-corrupting failure.

### Advisory lock (single-writer controller)
- v3 §8: one controller instance per project via a SQLite advisory lock.
- Implementation: `BEGIN IMMEDIATE` on a `scheduler_lock` table (one row).
  A second controller fails to acquire and exits.
- Phase 1 implements the lock primitive; the full controller lands in P3.

### Transaction isolation
- State transitions use `BEGIN IMMEDIATE` (acquire write lock at start, not
  at first write). This prevents the "reader upgrades to writer" deadlock
  pattern.
- If two writers compete, one gets `SQLITE_BUSY` and waits (busy_timeout),
  then either acquires (the other committed) or raises (deterministic).

### Concurrency tests (Phase 1 req §17)
- Two threads, same task transition → one succeeds, one gets
  `TransitionError` (state already changed) or `OperationalError` (lock).
- Two threads, different tasks → both succeed (no shared row contention).
- Duplicate idempotency requests → one succeeds, one is rejected by the
  unique constraint.
- The system never silently corrupts state — it either succeeds or raises.

## Revisions

None.

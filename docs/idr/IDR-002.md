# IDR-002: Build Backend — `hatchling`

**Status:** Decided (Phase 0)
**Date:** 2026-08-10
**Decides for:** How the `hermes` package is built for `pip install` / `uv sync`.

## Context

The project needs a PEP 517 / PEP 660 build backend that supports a `src/` layout with minimal coupling and no heavy framework. Foundation §4 mandates a minimal-core-dependency policy.

## Decision

Use **`hatchling`** as the build backend.

## Rationale

1. Minimal, standards-based PEP 517 backend — no project-management coupling (unlike `poetry-core`).
2. Already a very common choice; mature.
3. Plays cleanly with uv for resolution while keeping build and resolve concerns separate (consistent with IDR-001).
4. `src/` layout support is built in via `[tool.hatch.build.targets.wheel] packages = ["src/hermes"]`.

## Alternatives Considered

* **`setuptools`** — venerable, but heavier config and historically less-strict PEP 621 defaults.
* **`poetry-core`** — couples to the Poetry toolchain (foundation §3 warns against Poetry-by-familiarity).
* **`flit-core`** — minimalist; supports `src/` but lacks the wheel-target configuration flexibility we want.

## Consequences

* `[build-system]` pins `hatchling>=1.27`.
* `[tool.hatch.build.targets.wheel] packages = ["src/hermes"]` mirrors the layout in foundation §6.
* No runtime/coupling cost — hatchling is a build-time-only dependency.

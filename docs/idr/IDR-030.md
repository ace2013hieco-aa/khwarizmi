## The five decision points

### 1. Initial provider allowlist

**DECISION — RATIFIED:** the 11-provider scholarly set: **PubMed, PMC, EuropePMC, arXiv, OpenAlex, Crossref, Semantic Scholar, CORE, Unpaywall, bioRxiv, medRxiv.** Registry membership == allowlist membership (`get_adapter(provider_id)` raises `ProviderValidationError` outside the ratified set); a new provider enters only through the engineering plane with a `ProviderHazardSpec`, rate profile, parser, and golden fixtures — never at runtime (PA3/PX12 discipline).

**RATIONALE:** each provider is a contract card (§3) with endpoint, auth/polite params, pagination kind, rate profile, and known failure classes; the failure knowledge ships as versioned hazard-spec content driven by one generic evaluator (PS-02's "hazards as data" — zero per-provider judgment code). The set covers citation search (PubMed, EuropePMC, S2, Crossref), full text (PMC, EuropePMC, Unpaywall), and preprints (arXiv, bioRxiv, medRxiv) with per-provider retry taxonomy (§6.3).

**CONDITIONS:** (a) the **web-search row (Serper/Searxng) is NOT ratified by this record** — it is a separate row of the same decision, deferred (different endpoint/credential class — third-party keyed SaaS — and the contract explicitly does not design it; recorded as a standing item, not silently dropped); (b) no live network in CI — the opt-in `LIVE_SMOKE=1` P7 gate only, with the fixture-acceptance review gate (PS-10) before any new/adjusted recording merges.

### 2. Reconciliation semantics

**DECISION — RATIFIED:** per-provider verdicts `COMPLETE`/`SHORTFALL`/`UNKNOWN`; aggregates `PARTIAL` (returned-not-raised, recorded) vs `EMPTY` (typed `RetrievalShortfallError` — *searched, found nothing*) vs `UNAVAILABLE` (typed `ProviderUnavailableError` — *could not search*); the full zero-delivered matrix (mixed empty-and-down → `EMPTY` with causes in notes; `UNAVAILABLE` only if **no** provider ran, incl. routeable-to-no-adapter; valid-negative-only → `COMPLETE`-answered; valid-negative mixes → `COMPLETE` with causes in notes); `VALID_NEGATIVE` as a **result** (`valid_negative: true` + `valid_negative_for`), never a failure; `NO_FULL_TEXT` as a **result** at fetch scope (structured `no_full_text_kind` + `evidence_basis`), never a `FetchFailure`; `STOPPED_AT_LIMIT` is `COMPLETE`-with-note, never `SHORTFALL`; `CURSOR_TRAP` → `SHORTFALL(cause=CURSOR_TRAP)`; unknown hint prefix → `ProviderValidationError` before any I/O.

**RATIONALE:** this is the exact *"never a silent empty result"* reading the amendment requires (§30 rule 2) — an empty literature is surfaced as a typed failure, a down search is never confusable with "no literature exists" (PS-13/PS2-03/PS3-06), and a genuine "no" (identifier lookup answered, citation-only source) is a result, not a failure (PS-11/PS2-01/PS3-01/PS3-03). The reconciliation comparisons read `raw_retrieved_count` (pre-dedup) per the `counts_raw_rows` spec direction — never the post-dedup `delivered_count` (PS-04/PS2-05/PS2-09).

**CONDITIONS:** the aggregate is a *resolution* signal; per-source outcomes are the evidence signal — a consumer may not conclude full-text availability from the aggregate alone (PS3-04). The fetch verdict→outcome mapping table is complete and fail-closed: `VALID_NEGATIVE`/`CURSOR_TRAP`/`REWRITE_SUSPECT` are unreachable at fetch scope, and a scope error fails closed rather than falling through (PS3-01).

### 3. Redaction contract

**DECISION — RATIFIED:** credential-class aliases (config set: `api_key, apikey, key, token, access_token, auth, password, secret, signature, …`) redacted **wherever they appear** — URL query params, **path segments**, headers (`Authorization`, cookies), body fields; polite-pool identifiers (`email`, `tool`) sent on the wire but redacted in every record; **default-deny** for unknown param names + a `redaction_policy_gap` note; redaction applied **once, at the recorder boundary**, before logging/provenance/events/error messages; `RedactionError` fail-closes the request before issuance and **names the parameter, never its value**; exception-path rule structured — the transport is constructed with the `RedactionPolicy`, is the only component that raises provider errors, and raises `from None` **at every re-raise hop** (future wrappers, `ExceptionGroup`), so no `__cause__`/`__context__`/traceback path carries a raw URL; S6 secrets-out validator remains the write-path backstop.

**RATIONALE:** the PS-02/PS2-04/PS3-07 chain closed the credential-leak class the first gate found — including the leak *before* the S6 validator ever sees it (S6 validates records, not exception paths). The polite-pool class is preserved because the providers require the params on the wire but Hermes never stores them.

**CONDITIONS:** none beyond the contract's tests (§7.3): a real key value appears in zero records and zero exception messages; `email`/`tool` sent-but-redacted; unknown names default-denied; S6 passes on every fixture (contract §9 rows 15–16, 23, 33).

### 4. Rate-limit starting-point defaults

**DECISION — RATIFIED as starting-point defaults:** the §6.2 table — PubMed/PMC 3 rps burst 5 (10 rps with key; off-peak for batches), EuropePMC 3 rps burst 5 (serial walks), arXiv 1 rps burst 3, bioRxiv/medRxiv 1 rps burst 3, OpenAlex 10 rps polite burst 15, Crossref 5 rps (10 polite, concurrency 3), Semantic Scholar 1 rps burst 3 (honor 429), CORE per-key profile with daily cap, Unpaywall daily cap 10k. **Values are config, not code** — operator-adjustable, version-recorded in the request log's `provider_spec_version`, **validated at P7** against real literature tasks (the `C_MIN`/S6 precedent: where no published limit exists, the default is a conservative Hermes floor).

**RATIONALE:** recorded values from the audited source (published limits are ceilings; unpublished limits get conservative Hermes defaults — the honesty-instrument precedent). The `ProviderRateLimiter` is provider policy only; it is explicitly **not** the budget ledger.

**CONDITIONS:** the budget ledger (AR-02) remains **DEFERRED** — the IDR29-04 honesty note is preserved verbatim in the blueprint (§6.4): *bounded retrieval is enforced; bounded autonomy is not yet.* The limiter's caps are the only enforcement until the ledger lands. A daily cap is a hard stop recorded as `SHORTFALL(THROTTLED)`, never a hammer.

### 5. `total_is_estimate` + dedup-before-reconcile

**DECISION — RATIFIED:** `count_semantics ∈ {exact, estimate, absent}` per provider; Crossref `message.total-results` counts every version record and is an estimate → **dedup by DOI before comparing**, `total_is_estimate: true`; OpenAlex `meta.count` exact → `false`; Semantic Scholar `total` exact → `false`; PubMed/EuropePMC exact at query time → `false`, a corpus change mid-walk recorded via the `UNKNOWN`/note path, never silently. The **dedup-direction is per-provider spec content, never a driver guess** — `counts_raw_rows: true` (Crossref) means dedup before comparing; `false` means compare raw retrieved rows against `total` without pre-deduping (a provider whose pages legally repeat rows must not false-fire `SHORTFALL`). Spec-loading validation rejects incoherent combinations (`estimate` ⇒ `counts_raw_rows: true`; `absent` ⇒ `false`) **and** incoherent fetch rule sets (`body_required` without `body_marker`; fetch rules on a search-only provider; a fetch rule set that can never fire) — fail-closed at registration, never a runtime skip (PS2-09/PS3-05).

**RATIONALE:** the estimate-total rule is what makes the reconciliation comparisons truthful for the one provider whose totals are raw-row counts (Crossref); the registration validation keeps an incoherent spec from shipping a contradiction the driver would then have to interpret.

**CONDITIONS:** none beyond the §9 fixtures (rows 6, 25, 28–33).

## Decision

**Ratify the five §27 item 55 decision points as RESOLVED** against the remediated design (contract §9 rows 1–33 + blueprint, three review gates folded in). **Authorize Part 3 implementation of the provider slice** per the blueprint's §9 seven-step order — `normalize`/`redact`/port types → `hazards` → `walk` driver → `ratelimit`/`http` → the 11 adapters → `fetch_batch` → `replay` + the full fixture corpus — with the **manual-proof-first rule** (golden fixtures green before any scheduled execution) and the **engineering-plane adversarial review** (blueprint §9 step 7) as the hard implementation gate.

## Rationale

1. **The five decision points are resolved with fixture evidence, not intention.** Each maps to contract §9 acceptance rows: allowlist → rows 1–9/13–14; reconciliation → rows 10–12, 20, 26–27, 29, 32; redaction → rows 15–16, 23, 33; rate defaults → row 19; estimate-total → rows 6, 25. The catalog entries are the fixtures (row 1–9), so the ratified knowledge is test corpus, not prose.
2. **Three independent hostile gates found no structural defect.** All findings — including the three P1 triples (PS-01/02, PS2-01/02/03, PS3-01/02) — were folded into the design text, and the fold-in was verified by source grep (all 30 `PS-`/`PS2-`/`PS3-` markers present in blueprint and contract with their fixes). The design-level gate closes with no open P1/P2.
3. **Scope discipline is structural, not asserted.** The slice is read-only by construction (PA4 `READ_ONLY`, outbox-exempt), creates zero tables/events/intents/authorities, and hands outcomes to the task which routes through the ordinary write path — the only-entry-point invariant (PS-03) makes the limiter, hazard evaluator, redaction recorder, and future budget ledger unbypassable.
4. **The acceptance-with-PS3-verified path is the operator's call, exercised here** — the blueprint's explicit alternative to a fourth gate; the implementation-time adversarial review remains a hard step-7 gate regardless, so no review weakening occurs.

## Context

The surviving idea (framework §D.4, §H) is the forward question — "if A is
rejected/patched/changed, what else is affected" — distinct from provenance
(where something came from). The framework's own phase-0 gate (§M) resolved
against the live repository: the controller's eligibility check is LOCAL
(`_discover_eligible` gates direct deps only) and **nothing computes the
forward closure**; but `task_dependencies` already IS the ratified
`depends_on` edge set, so the first slice needs no new table, edge type,
event, or authority. The design gate (§9) answers every authority question:
the graph describes BLOCKED tasks while Q-02 orders ELIGIBLE ones and Q-05
labels failures — three read-only derivations, one writer of task state.

## 1. The contract (versioned, derived, read-only)

**Sources of truth (all ratified; nothing stored is derived — F2):**

| Fact | Ratified source | Read authority |
|---|---|---|
| edge set (depends_on) | `task_dependencies` (insert-only) | read-only SELECT |
| node state | `tasks.status` (`transition_status`) | read-only |
| failure label (why) | Q-05 `failure_classifications` digest | read-only digest |

**The predicate** is the TRANSITIVE version of the controller's own
eligibility rule, never a new blocking rule: a dependent is in the cone iff
it has a path from a seed through edges where **every edge's source node is
NOT SUCCEEDED** (F9: a SUCCEEDED intermediate breaks the chain — a task
whose direct dependency succeeded runs regardless of the seed). Entries are
labeled with the FIRST non-SUCCEEDED ancestor from the seed (root cause)
and its status, plus its Q-05 classification label when recorded.

**Outputs (all advisory):**

1. `failure_cone(seeds)` → `{task_id: (blocking_ancestor, status,
   classification_label|None)}` — on any FALSIFIED/retracted/failed source,
   every downstream task needing re-review.
2. `blocked_roots(project)` → tasks whose dependency closure contains a
   TERMINAL FAILED ancestor (permanently blocked until IDR-029 or a new
   iteration) — distinct from transiently blocked (RETRYING on the ladder).
3. `change_blast_radius(seeds)` → the full transitive dependent closure
   regardless of status — "what would this change affect".

**Determinism:** sorted seeds, sorted dependents, first-visit-wins,
cycle-defensive (visited set); `GRAPH_QUERY_VERSION="1"` bound into every
result hash (`graph_result_hash`): same state + same version ⇒ same
identity. Results are NEVER persisted — recomputed per query, so no
stored-version drift. No clock, no random, no LLM input in the traversal.

## 2. Authority boundary

- **CAN** surface affected downstream objects for re-review, labeled with
  the blocking edge and its Q-05 classification.
- **CANNOT** auto-retract, auto-invalidate, auto-fail, or auto-modify
  (framework §G — retraction authority stays where it lives).
- **CANNOT** change scheduling: `_discover_eligible`, the dependency gate,
  and the IDR-029 ladder are untouched.
- **CANNOT** write: structural check — no write SQL in `core/graph.py`.

## 3. Controller integration (read-only consumption)

`Controller.failure_cone` / `blocked_roots` / `change_blast_radius` mirror
`classification_proposals`: project-scoped read-only SELECTs
(`_load_task_graph_state`) fed through the pure functions, returned as
version-bound, hashed advisory dicts. No lock, no fence, no writes.

## 4. Deferred (explicitly NOT ratified here)

Artifact-level `conflicts_with` / `introduces_risk` edges require new edge
types in `provenance_edges` (schema change) and LLM-proposed edge existence
— deferred to the provenance-lineage phase; this design's traversal +
determinism contracts extend to it unchanged (§5 of the design gate).

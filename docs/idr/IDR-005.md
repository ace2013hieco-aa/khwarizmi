# IDR-005: Test Framework — `pytest`

**Status:** Decided (Phase 0)
**Date:** 2026-08-10
**Decides for:** How Hermes is tested at the unit and integration level.

## Context

Foundation §5 mandates pytest as the test runner, with "property/state-machine testing only where it provides concrete value."

## Decision

Use **pytest** as the primary test runner. Tests live in a top-level `tests/` directory (per the foundation layout) mirroring module boundaries. Property/state-machine tests (via `hypothesis` or similar) will be introduced at Phase 1+ where deterministic state-machine invariants warrant it.

## Rationale

1. Mandated by foundation §5.
2. Standard fixtures, parametrize, and capsys support cover Phase 0's needs.
3. `[tool.pytest.ini_options]` in `pyproject.toml` configures `testpaths=["tests"]` and `-q` for terse output.

## Alternatives Considered

* **unittest (stdlib)** — usable, but pytest is mandated and offers superior ergonomics (plain asserts, fixtures).
* **nose2** — unmaintained; irrelevant.

## Consequences

* `pytest` and `pytest-cov` live in `[dependency-groups] dev = [...]`.
* Running `pytest` (or `uv run pytest`) from the repo root finds all tests.
* Property-based testing will be introduced as a separate dev dependency when Phase 1 state-machine tests justify it.

# IDR-003: Configuration Format — stdlib `tomllib` + frozen dataclasses

**Status:** Decided (Phase 0)
**Date:** 2026-08-10
**Decides for:** How operator-controlled configuration is represented, loaded, and validated.

## Context

Foundation §8 mandates a typed, validated configuration schema, in a human-editable file (`config/hermes.toml`), with no heavyweight framework and secrets kept out (environment variables only). Foundation §4 mandates a minimal-core-dependency policy: prefer the Python standard library wherever practical.

## Decision

1. **Format:** TOML, loaded with the Python 3.14 stdlib `tomllib` module.
2. **Schema:** a tree of frozen (`frozen=True, slots=True`) dataclasses rooted at `HermesConfig` (`hermes/config.py`).
3. **Validation:** performed in code (`load_config`) with a `ConfigError` exception. Unknown keys are ignored for forward-compatibility; known-but-invalid types raise.
4. **Defaults:** every dataclass field has a default, so `default_config()` returns a valid config with no file.
5. **Secrets:** never in the TOML. Provider API keys, credentials, and hostnames are supplied via environment variables consumed by adapter code; `hermes doctor` does not print them.

## Rationale

1. `tomllib` is stdlib (Python 3.11+; we require 3.14). Zero dependency weight.
2. TOML is already the stated preference in foundation §8.
3. Frozen dataclasses give type-safety, attribute access, and immutability — no string-key access typos at runtime.
4. `slots=True` reduces memory and signals intent.
5. No third-party config framework (pydantic, dynaconf, etc.) is needed at Phase 0; we avoid the dependency and the validation-style lock-in.

## Alternatives Considered

* **pydantic** — excellent validation but adds a core dependency and validation style we don't need at the schema complexity of Phase 0. Revisit if/when validation rules grow past what dataclass constructors express.
* **YAML** — would require an external parser; TOML covers our needs with stdlib.
* **JSON** — no comments; less ergonomic for humans.

## Consequences

* `config/hermes.toml` is the canonical config file.
* `hermes.config.load_config(Path)` → `HermesConfig` is the only loading path.
* Adding a new config section = add a dataclass + a line in the sections map. Unknown keys in TOML are ignored (forward-compatibility).
* `hermes doctor` prints the resolved config values for operator visibility.

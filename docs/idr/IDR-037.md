## Context

IDR-036 ratified the pure failure-classification substrate and explicitly
deferred persistence "to when the Evidence Ladder lands (P2)". This slice
corrects that deferral: **the repository already has the exact carrier** for
advisory, content-addressed metadata. The generic `artifacts` table's
`artifact_type` column has **no CHECK constraint** — a new type value requires
no migration — and the `provenance_edges` table already supports the
`cites`/`derived_from` edge types (§14). The source slice and the CONTRA
claim/assumption slice established the pattern this slice reuses verbatim:
content-derived identity, project scoping, get-by-hash-first idempotency,
task-bound writes, zero new events.

The slice therefore lands the classification NOW through the same seam, and
defines the metadata-field contract the future REFUTED record will carry
(design D3) — so the ladder's P2 write path consumes a ratified contract
instead of inventing one.

**What this slice is NOT:** the Evidence Ladder; a REFUTED transition engine;
a hypothesis table; a new intent/gateway kind; a new event; a new authority;
a new scheduler; automatic hypothesis/task/scope creation. The classification
remains advisory metadata — never evidence, never a `Validation`, never
ladder-citable (v6 §29.2 boundary preserved).

## Decision

**Adopt the Q-05 persistence slice and its read-only consumption surface as
architecture. No authority moves, no new tables, no new events.**

### D1 — Persist as an `artifacts` row, not a new table

An ADMITTED classification is recorded through the existing
`ArtifactRepository.record` (inline JSON metadata, `inline://` storage path):

| Field | Value |
|---|---|
| `artifact_id` | `classification.classification_id` (`"fc_" + content_hash[:24]`) |
| `artifact_type` | `"failure_classification"` (open column — no migration) |
| `content_hash` | the substrate's canonical SHA-256 (re-derived at the write path) |
| `project_id` | the classification's project (project-scoped, like every artifact) |
| `task_id` / `producer` | the producing falsification task / `"falsification:<task_id>"` |
| `metadata` | the structured classification: class, contributing factors, evidence refs, class-specific citations, `classifier_version`, `classification_id`, `permitted_actions`, `requires_human_confirmation`, explanation, proposer, the record's full falsifying-evidence set, reason |

**Identity discipline (EC-V6):** the write path re-runs the substrate with the
REAL resolvers and re-derives identity from (`record`, `draft`) — it never
trusts a caller's ADMITTED claim or an authored hash. An optional `claimed`
classification is compared against the re-derivation; any mismatch is a
`FailureClassificationIntegrityError` and nothing is written.

### D2 — Provenance edges (existing `provenance_edges`, no new types)

Written atomically with the row (IDR-013), dependent-first
(`(artifact_id, upstream_id, edge_type)` — house convention):

1. `(classification_id, evidence_ref, "cites")` for **each** falsifying
   evidence artifact the classification cites.
2. `(classification_id, producing_task_id, "derived_from")` — the producing
   falsification task.
3. Future (ladder lands): the REFUTED record carries a metadata field
   `failure_classification_ref` (D3) and a `cites` edge from the record to the
   classification — the classification stays advisory (the RECORD cites it,
   never the reverse).

Reclassification under a new `classifier_version` is a new content hash → new
artifact row (`content_hash` UNIQUE); both rows coexist — historical truth is
never mutated.

### D3 — The metadata-field contract on the future REFUTED record

When the Evidence Ladder lands (P2), its falsification/REFUTED record carries
the classification as a metadata field:

```json
{
  "failure_class": "DECLARED_CONSTRAINT_VIOLATION",
  "classifier_version": "q05-2026.1",
  "classification_id": "fc_<24 hex>",
  "failure_classification_ref": "failure_classification:<content_hash>"
}
```

The ref is a **dereference contract** (the `research_program:` provenance
pattern, V6-FINAL-02): at the ladder's write path the ref MUST resolve via
`dereference_failure_classification_ref` to an `artifacts` row of type
`failure_classification` in the same project, or the record fails closed.
`failure_class`/`classifier_version`/`classification_id` are denormalized for
readability; the ref is the authority.

### D4 — Authorization: task-bound, zero new intents

The classification is advisory metadata, not a state mutation — recording it
needs **no new intent** and no gateway change. The write is authorized by
binding, checked INSIDE the write transaction (V6-P7-A2-02 TOCTOU closure):
the producing task exists, is same-project, and is RUNNING at commit time; the
classification's evidence refs all belong to the producing task's outputs
(two-hop `derived_from` reachability — the `_source_artifact_resolves`
precedent) and are the record's falsifying evidence; the classification is
ADMITTED by the substrate re-run with real resolvers. A second, future
authorization surface is the ladder's own REFUTED transition — the
classification is then recorded as part of an already-authorized
falsification, not independently.

### D5 — Resolver wiring (the write path supplies the real resolvers)

| Resolver | Real source | Status |
|---|---|---|
| `evidence_resolver(project_id, ref)` | `artifacts` + project-edge reachability (`_source_artifact_resolves`) — a `failure_classification` ref is REFUSED (D8) | AVAILABLE |
| `constraint_resolver(project_id, program_ref, ref)` | `research_programs` row: `hypothesis:<H>:falsification_condition` / `methodology_constraint:<i>` | AVAILABLE |
| `mechanism_resolver(project_id, program_ref, ref)` | program `predictions[].ref` (`prediction:<P>`) | AVAILABLE |
| `scope_field_resolver(project_id, brief_ref, field)` | `scope_briefs.scope_text_json` key presence (OQ-1: the brief has no closed schema — non-dict brief text fails closed) | **DEFERRED — fail closed until a ScopeBrief creation path lands** (red-team §3: no production `INSERT INTO scope_briefs` exists — the resolver always fails closed, which is SAFE but was mislabeled AVAILABLE) |
| `regime_resolver(project_id, ref)` | the regime axis store (ICSS-v1) — **does not exist yet** | **DEFERRED — fail closed** |

An `ENVIRONMENT_MISMATCH` classification is therefore **not admissible at the
write path** until the regime axis lands: the substrate can admit it with an
injected stub resolver, the write path refuses it (explicit DEFERRED refusal
+ the re-run's absent resolver). The asymmetry is documented, not papered
over.

### D6 — Idempotency / one-shot (the artifacts-table engine)

- **Identical content** (same record + draft + classifier version): same
  `content_hash` → get-by-hash-first (SD-04) → reuse the existing row, no new
  row, no duplicate edges (INSERT OR IGNORE) — crash/retry idempotent. A
  reused row is never rewritten (immutable; `reason` is audit-only on NEW
  loudly (R02 guard — never silently reused).
- **New classifier version** (legitimately new content): new row, both records
  coexist — versioning semantics, NOT the divergent one-shot refusal of source
  outcomes (a reclassification is a new derivation, not a divergent output).

### D7 — Zero new events

The artifact row + provenance edges ARE the audit record (the IDR-028 D3
precedent). The producing task's own lifecycle events already journal the
execution; `EVIDENCE_TRANSITION_*` events remain reserved for the ladder's own
transitions (P2). The slice writes no events.

### D8 — Read-only consumption surface (advisory only)

A read query over `artifacts` (`artifact_type = 'failure_classification'`,
project-scoped) + `provenance_edges` answers "what classifications exist for
hypothesis H / evidence E". The consumption surface is a **pure digest**:

- `classifications_digest(rows)` — deterministic, versioned (`DIGEST_VERSION`)
  advisory digest grouped by hypothesis: failure class, classifier version,
  the taxonomy's own `permitted_actions` proposals,
  `requires_human_confirmation`, cited evidence, and the D3
  `failure_classification:<hash>` ref. Pure: no SQL, no writes, no authority —
  the ActionEvaluation posture (`evaluation.py`). A malformed row is skipped,
  never fails the digest open.
- `Controller.classification_proposals()` — the reconcile/controller loop's
  read-only accessor: feeds the repository read query through the digest so
  the Director can surface permitted-action proposals. Rebuilt over the
  fenced connection on every lock acquisition; never writes.

The classification artifact is **never dereferenceable as evidence** — no
resolver outside the slice may cite it as a `source_result`/`Validation`/ladder
precondition (structural: its `artifact_type` is outside every citable type
set, and the evidence resolver refuses it explicitly).

## Rationale

1. **The gap the slice closes is the one IDR-036 left open.** The substrate
   defined the record shape but had no persistence. This slice lands the
   classification through the repository's own content-addressed artifact
   engine — the same seam the source and CONTRA slices use — so the future
   ladder consumes a ratified write path instead of building one.
2. **Small and subordinate.** One repository class (the
   `SourceOutcomeRepository.record` shape), a real resolver bundle, a pure
   digest, and a read-only controller accessor. No table, no intent, no
   gateway change, no event, no scheduler, no state machine — the slice's
   only writes are the artifact row + `provenance_edges`.
3. **Identity is derived, never authored.** The write path re-runs the
   substrate with real resolvers; a caller can never persist a REJECTED or
   forged classification. Task binding inside the transaction closes the
   TOCTOU window; evidence must belong to the producing task.
4. **Regime gap fails closed.** ENVIRONMENT_MISMATCH is refused at the write
   path until the ICSS-v1 regime axis exists — documented asymmetry, never a
   silent pass.
5. **The consumption surface is advice, not authority.** The digest computes
   nothing beyond the ratified action map and executes nothing; the Director
   remains the only actor. FRAMING_ERROR still requires human confirmation
   and the S16 scope path; RESOURCE_CONSTRAINT never expands a budget.

  `failure_classification_ref` + the dereference contract, the D4 task-bound
  authorization, and the D8 read surface — the classification is a metadata

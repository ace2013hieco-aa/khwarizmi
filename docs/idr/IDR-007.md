# IDR-007: SQLite Schema Design — Phase 1

**Status:** Decided (Phase 1)
**Date:** 2026-08-10
**Decides for:** Database table structure for the Hermes state/persistence substrate.

## Context

v3 §16.4 mandates SQLite (WAL mode) as the day-one system of record. v3 §7
requires persisted node/edge tables. v3 §8.1 requires an append-only events
table. v3 §16.1 requires artifact metadata. v3 §14 requires provenance edges.

The schema must support queryable authoritative state — not generic JSON blobs
where v3 requires explicit columns and constraints.

## Decision

Five core tables in schema version 1:

### `schema_version`
- `version INTEGER PRIMARY KEY` — the applied schema version
- `applied_at TEXT NOT NULL` — UTC ISO-8601 timestamp of application

### `projects`
- `project_id TEXT PRIMARY KEY` — UUID
- `name TEXT NOT NULL`
- `lifecycle_state TEXT NOT NULL` — must be a valid §6.1 state (CHECK constraint)
- `operational_mode TEXT NOT NULL DEFAULT 'ACTIVE'` — ACTIVE | AWAITING_HUMAN | PAUSED
- `iteration INTEGER NOT NULL DEFAULT 1` — current research iteration
- `created_at TEXT NOT NULL` — UTC ISO-8601
- `updated_at TEXT NOT NULL` — UTC ISO-8601
- CHECK constraints: `lifecycle_state IN (...)`, `operational_mode IN (...)`

### `tasks`
- `task_id TEXT PRIMARY KEY` — UUID
- `project_id TEXT NOT NULL REFERENCES projects(project_id)` — FK with ON DELETE CASCADE
- `task_type TEXT NOT NULL` — AGENT_TASK | TOOL_TASK | GATE | HUMAN_GATE | SUBGRAPH
- `profile TEXT` — DIRECTOR | RESEARCHER | IMPLEMENTER | ADVERSARY | DETERMINISTIC (nullable for non-agent tasks)
- `idempotency_key TEXT NOT NULL` — content hash of spec+inputs
- `attempt INTEGER NOT NULL DEFAULT 1`
- `status TEXT NOT NULL DEFAULT 'PENDING'` — must be a valid §6.3 status (CHECK constraint)
- `iteration INTEGER NOT NULL DEFAULT 1` — which research iteration this task belongs to
- `parent_task_id TEXT` — for subgraph tasks (nullable)
- `spec_json TEXT NOT NULL` — typed, schema'd spec (JSON for metadata, not authoritative state)
- `inputs_json TEXT` — list of artifact_ref (JSON array, metadata)
- `outputs_json TEXT` — list of declared artifact kinds (JSON array, metadata)
- `provenance_json TEXT` — upstream artifact ids (JSON array, metadata)
- `cost_class TEXT`
- `concurrency_group TEXT`
- `max_retries INTEGER NOT NULL DEFAULT 3`
- `created_at TEXT NOT NULL`
- `started_at TEXT`
- `completed_at TEXT`
- `last_heartbeat TEXT`
- UNIQUE constraint: `(idempotency_key, attempt)` — prevents duplicate execution
- CHECK constraint: `status IN (...)`

### `task_dependencies`
- `dependency_id INTEGER PRIMARY KEY AUTOINCREMENT`
- `task_id TEXT NOT NULL REFERENCES tasks(task_id)` — FK,CASCADE
- `depends_on_task_id TEXT NOT NULL REFERENCES tasks(task_id)` — FK,CASCADE
- `created_at TEXT NOT NULL`
- UNIQUE constraint: `(task_id, depends_on_task_id)`
- CHECK constraint: `task_id != depends_on_task_id` — no self-loops

### `events`
- `event_id INTEGER PRIMARY KEY AUTOINCREMENT` — monotonic, append-only
- `event_type TEXT NOT NULL` — from v3 §8.1 catalog
- `project_id TEXT REFERENCES projects(project_id)` — nullable (some events are project-scoped)
- `task_id TEXT REFERENCES tasks(task_id)` — nullable
- `from_state TEXT` — previous lifecycle/task status (nullable for creation events)
- `to_state TEXT` — new lifecycle/task status
- `correlation_id TEXT NOT NULL` — UUID linking related events in a transition
- `caused_by TEXT` — who/what initiated
- `reason TEXT` — why
- `artifact_ids_json TEXT` — JSON array of artifact references
- `payload_json TEXT` — structured event-specific data
- `created_at TEXT NOT NULL` — UTC ISO-8601 microsecond
- No UPDATE or DELETE path exposed through the repository API

### `artifacts`
- `artifact_id TEXT PRIMARY KEY` — UUID
- `project_id TEXT REFERENCES projects(project_id)` — nullable
- `task_id TEXT REFERENCES tasks(task_id)` — nullable
- `artifact_type TEXT NOT NULL` — typed kind (Hypothesis, BacktestResult, etc.)
- `content_hash TEXT NOT NULL` — SHA-256 of canonical bytes
- `size_bytes INTEGER NOT NULL`
- `storage_path TEXT NOT NULL` — relative path within artifact root
- `producer TEXT NOT NULL` — who produced it
- `metadata_json TEXT` — extensible metadata
- `created_at TEXT NOT NULL`
- UNIQUE constraint: `content_hash` — dedup by content identity
- INDEX on `content_hash` for lookup

## Rationale

- Explicit columns for all authoritative state (lifecycle_state, operational_mode,
  status) — no JSON blobs for queryable state (Phase 1 req §3).
- JSON used only for genuinely extensible metadata (spec_json, inputs_json,
  provenance_json, metadata_json) — per Phase 1 req §3.
- CHECK constraints mirror the v3 transition tables at the DB level —
  defense-in-depth alongside the Python transition API (v3 §26).
- Foreign keys with CASCADE ensure graph integrity.
- `events.event_id` is AUTOINCREMENT — monotonic ordering, append-only,
  never reused.
- `idempotency_key` unique constraint prevents duplicate execution.

## Revisions

None.

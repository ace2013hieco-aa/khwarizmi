# IDR-018: ResearchProgram — Approved Epistemic Contract (MERGE INTO EXISTING COMPONENT)

**Status:** Decided + implemented (P2 slice)
**Date:** 2026-08-12
**Decides for:** Whether Hermes adopts an "Epistemic Compiler" and, if so, in what form. Also records the P2 implementation scope of the adopted form.

## Context

An external proposal asked Hermes to adopt an "Epistemic Compiler" — a subsystem that transforms a research question into an executable research program (hypotheses, rivals, predictions, required evidence, gate requirements, task graph). The proposal was reviewed in three parts:

- **Part 1 (adversarial/protest review):** the compiler *service* was rejected — it would duplicate the Director's planning authority (v4 §13), the Intent Gateway's per-kind validation (v4 §8), GR7's task-graph templates, and S3's gap-driven task proposal. What survived was the *representation gap*: Hermes has no governed, versioned artifact that states the project's epistemic contract — what must be established, tested, verified, or falsified — nor a deterministic completeness check between that contract and the §10.2 ladder preconditions.
- **Part 2 (reconciliation + amendment):** verdict **MERGE INTO EXISTING COMPONENT**. Adopt a typed, immutable `ResearchProgram` artifact produced by the Director as a schema'd proposal, validated by a deterministic `ResearchProgramValidator` (a new row in the §5 deterministic-services family), admitted through the Intent Gateway (`PROPOSE_RESEARCH_PROGRAM`, Director-only), human-approved at the existing §9.1 gates, and instantiated into the task graph only via ordinary `INSERT_TASK`/GR7 mechanisms. No compiler service. The E-invariants (E1–E9), the verdict semantics (`COMPILED | INCOMPLETE | CONTRADICTORY | UNSUPPORTED | INVALID` with structured `CompilationError[]`), and the phase landing points (schema+validator P2, gateway wiring P3, Director variant P4, GR7 template instantiation P6, `DiscriminationRequirement` binding on `ExperimentSpecification` P8, graph-sourced rivals P7/P8) were specified.
- **Part 3 (implementation):** this IDR records the P2 slice that was actually landed.

## Decision

**The Epistemic Compiler as a subsystem is rejected. The `ResearchProgram` artifact + deterministic validator is adopted (MERGE INTO EXISTING COMPONENT).** The P2 slice is implemented:

1. **Domain model + validator — `hermes/research/programs.py`.** `ResearchProgram`, `Prediction`, `DiscriminationRequirement`, `HypothesisSpec`, `EvidenceRequirement` (derived), verdict semantics, `CompilationError`, `ResearchProgramDraft`, `compile_research_program` / `compile_from_payload` (the P3 gateway wiring point). Deterministic: `content_hash`/`input_hash` are SHA-256 over canonically sorted serializations; `program_id = "rp_" + content_hash[:24]`; no clock, no random, no unordered iteration. E1–E5 checked; E2/E3 guard the §10.2 obligation map; E6/E7/E8/E9 enforced structurally (no write path in the validator; closed payload schema; versioning-only change path). Rival coverage and the E5 distinguishability rule (no checkbox rivals) implemented.
2. **Intent — `hermes/core/intents.py`.** `PROPOSE_RESEARCH_PROGRAM` added to the LLM-proposable kinds and to a new `director_only()` set.
3. **Event — `hermes/core/events.py` + `persistence/event_validation.py`.** `ResearchProgramCompiled` added to the catalog and the persistence-boundary allowlist (F-15 applied — both places updated).
4. **Migration — `persistence/migrations.py` (3 → 4).** `research_programs` table mirroring `scope_briefs`: content-derived `program_id` PK, `version`, `supersedes_id`, `UNIQUE (project_id, version)`, `UNIQUE (project_id, content_hash)` (idempotency at DB level), `CHECK (supersedes_id != program_id)`.
5. **Repository — `persistence/repositories.py`.** `ResearchProgramRepository` with the validate-before-write contract: only a `COMPILED` result may be persisted (E6/E7 — enforced both structurally by the validator, which has no write path, and at the write path by the COMPILED-only gate plus the integrity boundary, EC-V6-11..16), the frozen `ScopeBrief` must exist for the project and the program must have been compiled against its DB-resolved content hash (governance, R-02), supersession must target the current chain head and must change content (E9), duplicates are idempotent (PA4), and there is no UPDATE/DELETE path (immutability is structural). The write emits `ResearchProgramCompiled` atomically (IDR-013).
6. **Tests — `tests/test_research_program.py` (45 tests, plus the R-01..R-04 / EC-F01/F02 / EC-V6-11..20 regressions below).** AC-01..04, 06..09, 11; all five verdicts; repository contract; migration (fresh/replay/v3→v4 upgrade/future-version rejection/FK integrity); intent contract; adversarial cases A–L scoped to P2.

## Rationale

1. **The gap is representational, not authoritative.** Hermes already owns every verb the compiler proposed: planning (Director), validation (gateway/§5), operational shape (task graph/GR7), round-level instantiation (S3). What was missing is the artifact those owners produce and consume — the epistemic contract. Adding authority without adding capability is the exact failure mode the review's final rule prohibits.
2. **Determinism and identity.** A compiled program must be reproducible: identical inputs + version triple ⇒ identical `content_hash`/`program_id`. Identity is content-derived; the version triple (`compiler_version`/`policy_version`/`schema_version`) and governing inputs (`scope_content_hash`, refs) are hashed in; provenance fields (`created_at`/`created_by`/`version`) live on the row, never inside the hash.
3. **No second authority system.** The program has no write path. The only mutation is the gateway-admitted proposal → repository write; tasks are never touched. Evidence status is unrepresentable (closed schema + no status fields — E8).
4. **Phase honesty.** The P2 slice deliberately excludes: gateway wiring (`apply_intent` is a P3 placeholder on this baseline; `compile_from_payload` is the exact entry the P3 per-kind validator will call), the Director drafting variant (P4), GR7 template instantiation (P6 — a non-null template ref is `UNSUPPORTED` until the template registry exists), `DiscriminationRequirement` binding on `ExperimentSpecification` (P8), and graph-sourced rivals (P7/P8). Predictions/discrimination requirements are structured inline entries with stable refs; their promotion to first-class artifact tables is P8.

## Consequences

- **Implemented:** the P2 slice above. Full suite: 333 passed (45 new), Python 3.14.1.
- **Authority boundaries:** the capability CAN define obligations (derived evidence/gate requirements from declared ladder targets) and CAN be inspected (repository reads + `summarize()`); it CANNOT promote evidence, write tasks, bypass the gateway, or mutate any prior program.
- **Deferred (explicitly not implemented):** P3 gateway wiring; P4 Director drafting variant; P6 GR7 template registry + instantiation (cyclic-template DAG check lands there — the current `UNSUPPORTED_TEMPLATE` verdict is the safe P2 posture); P8 `ExperimentSpecification.discriminates` binding + `Prediction`/`DiscriminationRequirement` table promotion; P7/P8 graph-sourced rivals and projection edges.
- **Known conservative choice:** a supersession with unchanged content is rejected (a new version must change the contract); reverting to a prior contract's exact content is blocked by `UNIQUE (project_id, content_hash)` — a reversion is a new version with different content (e.g., a re-stated objective), never a duplicate row.

## Remediation addendum (post-implementation hostile re-verification, 2026-08-12)

Three defects were confirmed and fixed (each with a regression test in `tests/test_research_program.py::TestRemediation`):

- **R-01 (determinism, P1):** `_canonicalize` sorted lists of dicts only by a `ref` key; DERIVED `evidence_requirements` (keyed by `claim_ref`) therefore followed hypothesis input order, so a program with two confirmatory hypotheses compiled to a different `content_hash` when the hypotheses were given in a different order. Fixed by sorting all dict-lists by their canonical JSON. Regression: `test_r01_determinism_two_confirmatory_order_invariant`.
- **R-02 (governance at the write path, P1):** `record()` verified the frozen `ScopeBrief` existed but never verified the program was compiled against that brief's actual content hash — a caller could compile with any non-null `scope_content_hash` and persist. `ResearchProgram` now carries `scope_content_hash`, and the repository compares it against the DB-resolved brief hash, rejecting a mismatch. Regression: `test_r02_write_path_rejects_bogus_scope_hash` / `..._accepts_matching_scope_hash`.
- **R-03 (LLM boundary fail-open, P2):** `_draft_from_payload` coerced non-string fields with `str(...)` (a numeric `ref` became `"123"`). Replaced with strict `_require_str` typing — malformed output is `INVALID`, never coerced. Regression: `test_r03_non_string_ref_fails_closed` / `..._objective_fails_closed`.
- **R-04 (hardening):** added a deterministic failure-injection test (a trigger aborts the INSERT) proving the write is atomic — no program row and no `ResearchProgramCompiled` event remain on mid-write failure (IDR-013).

Post-fix suite: 339 passed. The final architecture/implementation gate remains an external independent verification step; this addendum is not a self-issued clearance.

## Final-gate closures addendum (v6 session, 2026-08-12)

The Part 6 final independent gate returned **RELEASE WITH CONDITIONS** and raised two P3 findings, both **closed in the v6 session** (regression tests in `tests/test_research_program.py::TestRemediation`):

- **EC-F01 (closed-schema nesting, P3):** unknown keys *nested inside* hypothesis/prediction/discrimination entries were silently dropped rather than rejected — the payload-level unknown-key check only covered the top level, so `hypotheses[0]["status"] = "SUPPORTED"` or a nested `sql`/`bypass`/`gate_override` key vanished on compile with no error and no state impact. The schema validation is now **recursive**: every nested entry is checked against its exact allowed key set and unknown keys produce `UNKNOWN_PAYLOAD_KEY` errors with the precise `field_path` (e.g. `payload.hypotheses[0]`). Regressions: `test_ecf01_nested_unknown_keys_rejected`, `test_ecf01_nested_unknown_keys_predictions_and_discrimination`.
- **EC-F02 (typed-draft verdict contract, P3):** `compile_research_program` on a malformed *typed* `ResearchProgramDraft` (e.g. a numeric `ref`) raised an uncaught `TypeError` instead of returning a verdict — violating the fail-closed contract that malformed LLM output must produce a deterministic `INVALID` result. The typed entry now validates the draft's fields and returns an `INVALID` verdict with `MALFORMED_DRAFT` errors, never raising. Regressions: `test_ecf02_typed_draft_fails_closed`, `test_ecf02_valid_typed_draft_still_compiles`.

Post-closure suite: 374 passed (339 + 35 new v6 tests: 31 ActionEvaluation + 4 EC closures). The external independent closure gate remains the standing condition per v6 §27 item 43; this addendum is not a self-issued clearance.

## Integrity-boundary remediation addendum (v6 Step 5, 2026-08-13)

The hostile trust-boundary re-verification (v6 §28.2 trust model, findings EC-V6-11..16 in `docs/idr/hermes_v6_step4_trust_boundary_report.md`) confirmed that E6/E7's "no direct mutation bypass" was **overclaimed as it stood**: a caller with a DB handle could hand-build a self-consistent `COMPILED` object and persist it — the write path gate checked the *verdict*, not the *object*. That claim is hereby corrected and closed with a structural integrity boundary (Model D — layered trust; one deterministic derivation, never two):

- **EC-V6-11 (identity, P2):** the repository now re-derives `content_hash` (over the canonical content dict), `program_id` (`"rp_" + hash[:24]`), and `input_hash` (over the governance inputs) with the compiler's own pure helpers (`content_hash_of` / `input_hash_of` / `program_id_of` / `canonical_content_dict` in `programs.py` — `_build_program` itself was refactored to use them, so the genuine path is byte-identical). Any caller-authored identity field is rejected. This also kills the Step 4 idempotency-collision: a *different* program can no longer return an existing row via a forged shared `content_hash`.
- **EC-V6-12 (program_id derivation):** covered by EC-V6-11 (program_id must equal `"rp_" + content_hash[:24]`).
- **EC-V6-13 (input identity):** covered by EC-V6-11 (`input_hash` re-derivation).
- **EC-V6-14 (obligation integrity, P2):** declared `evidence_requirements`/`gate_requirements` must equal `derive_program_obligations(hypotheses)` — the same derivation the compiler applies. Obligations are derived, never declared; a self-consistent forgery over empty obligations is rejected.
- **EC-V6-15 (version identity, P2):** `schema_version` must equal the implemented `PROGRAM_SCHEMA_VERSION` (self-consistent forgeries of it are rejected); tampering with `compiler_version`/`policy_version` *without* re-deriving identity is caught by the content-hash check. A *self-consistent* forged version is not an integrity violation — version validity is the validator's epistemic domain, and the repository applies no whitelist (v6 §4.4).
- **EC-V6-16 (fail-closed boundary):** every mismatch raises `ResearchProgramIntegrityError` (subclass of `ResearchProgramError`, so existing `pytest.raises(ResearchProgramError)` contracts still hold) **before** the transaction — no row, no `ResearchProgramCompiled` event, no partial state.

**Explicitly not introduced:** no re-run of the epistemic validator at the write path (the repository re-derives *identity and derived state*, it does not re-adjudicate semantics), no gateway (admission remains P3-deferred), and no authorization on `produced_by` — it is informational provenance (E9), and a genuine compile persisting `produced_by="DIRECTOR"` is preserved and tested.

Regressions in `tests/test_research_program.py::TestIntegrityBoundary`: `test_ec_v6_11_forged_content_hash_rejected`, `test_ec_v6_11_forged_program_id_rejected`, `test_ec_v6_13_forged_input_hash_rejected`, `test_ec_v6_14_obligation_divergence_rejected`, `test_ec_v6_15_forged_schema_version_rejected`, `test_ec_v6_15_stale_version_tamper_rejected_by_identity`, `test_ec_v6_16_multi_field_forge_rejected`, `test_ec_v6_17_genuine_compile_persists`, `test_ec_v6_18_genuine_idempotent_duplicate_returns_existing`, `test_ec_v6_20_validator_compiled_survives_helpers`.

Post-fix suite: **384 passed** (374 + 10 EC-V6 regressions), Python 3.14.1. Post-fix attack battery (multi-field forge, hash-collision, obligation divergence, self-consistent schema forgery, R-02 governance, provenance): all fail closed or persist as documented. The external independent closure gate remains the standing condition per v6 §27 item 43; this addendum is not a self-issued clearance.

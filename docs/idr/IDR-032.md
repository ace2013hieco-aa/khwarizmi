## Audit 1 — S6-A1…A5 (hermes_researchsourceprovider_step6_code_audit.md)

3 P1s, 1 P2, 1 P3, all reproduced by live probes and folded in:

- **S6-A1 (P1)** — resolver ignored the ref TYPE prefix: `source_result:<payload-hash>`
  resolved True and admission accepted it. Fixed: `_source_artifact_resolves`
  matches the artifact type; the ref prefix IS the type (dereference_ref +
  gateway admission pass it).
- **S6-A2 (P1)** — the provider mix check missed a SINGLE contradicting
  result provider (forged arxiv-log + pubmed result recorded). Fixed: the
  log and delivered results must AGREE when both are present.
- **S6-A3 (P1)** — a handler returning a non-`HandlerResult` silently
  SUCCEEDED the task. Fixed: `isinstance(result, HandlerResult)` required;
  anything else FAILs loudly.
- **S6-A4 (P2)** — `load_search_results` was `task_id`-based and missed
  REUSED (cross-project) rows while the resolver found them. Fixed: edge-based
  two-hop selection; the two read surfaces agree.
- **S6-A5 (P3)** — reused outcome-row metadata is audit-only scope-honesty,
  documented (OB-04).

5 regression fixtures; 874 passed suite-wide, pyright 0 errors.

## Audit 2 — S6-B1…B3 (hermes_researchsourceprovider_step6_code_audit2.md)

Second-gate attack on ONLY the S6-fixed surfaces. 2 P2s, 1 P3 pin, all
reproduced and folded in:

- **S6-B1 (P2)** — `discard(None)` silently dropped provider-less results
  from the agreement check; a provider-less record landed under a
  provider-bound task. Fixed: a result declaring no provider is REFUSED at
  the binding.
- **S6-B2 (P2)** — a handler returning `completed` WITHOUT recording anything
  SUCCEEDED the task. Fixed: the completed branch STRUCTURALLY verifies the
  task's outcome rows before SUCCEEDED; a zero-row "success" is FAILED.
- **S6-B3 (P3)** — the resolver's `artifact_type` had an unfiltered default.
  Fixed: the type is a REQUIRED parameter (all three call sites pass it).

3 regression fixtures; 877 passed suite-wide, pyright 0 errors.

## Audit 3 — S6-C1…C4 (hermes_researchsourceprovider_step6_code_audit3.md)

Third-gate attack on the S6-B surfaces + the provider-agreement rule × EMPTY
outcomes. 1 P2 + 3 PASS pins:

- **S6-C1 (PASS pin)** — the provider-agreement rule handles EMPTY correctly
  (matching log records; mismatched log refused; no-log refused, fail-closed).
- **S6-C2 (P2)** — a handler could misbind an outcome to ANOTHER RUNNING
  source task (a crashed worker whose heartbeat is still within the lease
  window): the A2-01/02 checks verify template/project/RUNNING but nothing
  tied the outcome to the DISPATCHED task. Fixed at the dispatch seam — the
  controller wraps the per-tick bundle in a task-scoped `TaskScopedSourceRepos`
  whose `record()` FORCES the cited task to the dispatched task; every
  handler (factory-built or custom) receives the scoped surface; a
  cross-task citation exhausts to FAILED, never a misbind.
- **S6-C3/C4 (PASS pins)** — the per-task structural completion check and the
  required resolver type hold.

3 regression fixtures; 880 passed suite-wide, pyright 0 errors.

# IDR-025: CONTRA P7 substrate — ResearchClaim / ResearchAssumption + ClaimAssumptionValidator (golden fixtures)

**Status:** Implemented + Tested (deterministic core only). The P7 runtime integration (extraction-task pipeline, persistence-with-events, write-path dereference) is explicitly **DEFERRED** — see §29.5 of the v6 document and the manual-proof-first rule (v6 §29.2 rule 7, §27 item 52).
**Date:** 2026-08-13
**Decides for:** The Part 3 implementation of the P7 substrate adopted by IDR-024 (ResearchClaim / ResearchAssumption artifacts + `ClaimAssumptionValidator`), delivered per the manual-proof-first rule as a golden-fixture, deterministic, no-write core.

## Context

IDR-024 (Part 2 reconciliation) decided that the CONTRA amendment package enters v6 as candidate amendment text (v6 §29, DESIGNED). The P7 row of the §29.4 phase table defines the acceptance for the substrate:

> `ResearchClaim`/`ResearchAssumption` + `ClaimAssumptionValidator` | P7 | deterministic claim identity; assumption↔claim links maintained; dangling context refs rejected; never-evidence structural test

§27 item 48 adds the binding constraints: content-addressed, immutable, supersession-edged, project-scoped, advisory §16 artifacts — never a `Validation`, never ladder-citable, never a gate input (PA2/GR3 verbatim); `ResearchClaim` relates to the §10.2 `Claim` by citation only (CT-R2); assumptions can never bear obligations (CT-R3).

## What was implemented (and why this scope)

Per the manual-proof-first rule, this step delivers the **deterministic core only** — the domain model, the validator, and the golden fixtures. The extraction-task pipeline (LLM tasks proposing extractions), persistence with events, and the real write-path dereference resolver are P7 runtime integration and are deferred, exactly as IDR-024's "no new event" and "zero new authority" constraints require. The substrate is pure: no DB, no clock, no writes, no event surface.

**`src/hermes/research/claims.py`:**

- **`ResearchClaim`** — atomic assertion extracted from a research artifact: statement, `source_ref` ("artifact_type:ref" form), optional `span_ref`, advisory `claim_type` (≤64 chars), closed-vocabulary context tags, resolved `assumption_ids[]`. Content-addressed identity `cl_<sha256(canonical)>[:24]` derived from statement + source/span refs + claim_type + context tags — never from batch refs, provenance, or creation data (AC-01 discipline).
- **`ResearchAssumption`** — declared premise: statement, context tags, `supporting_artifact_refs[]`, `dependent_claim_ids[]` (maintained deterministically by the validator), advisory status ACTIVE/SUSPENDED/SUPERSEDED. Content-addressed identity `as_<sha256(canonical)>[:24]`.
- **`validate_extraction`** (the `ClaimAssumptionValidator` entry point) — mirrors the ResearchProgramValidator pattern (`compile_from_payload`): closed-schema validation (empty batch, duplicate batch-local refs, empty statements, malformed `source_ref`/span/claim_type, unknown context dimensions, non-string tag values), batch-local assumption_ref resolution, optional authoritative dereference via an injected `context_resolver` (`dataset_ref` → DatasetManifest, `regime` → the ICSS-v1 axis), content-derived identity, deterministic dependent-claim maintenance, and self-supersession rejection. Fail-closed: returns `ExtractionResult` (verdict + collected errors), never raises (except a non-`ExtractionDraft` argument, which is a caller-contract error).

**`tests/test_claims.py`** — 26 golden-fixture tests proving the §29.4 P7 acceptance row:

1. **Deterministic claim identity** — same content ⇒ same id across batches; batch refs and `extracted_by` provenance never enter identity; content sensitivity (statement/source/span/type/context each change the id); `cl_`/`as_` prefix + hash-length form; content_hash == identity (single derivation, EC-V6-20 discipline for programs).
2. **Assumption↔claim links** — `dependent_claim_ids` back-references complete and sorted; assumption identity independent of which claims depend on it.
3. **Dangling context refs rejected** — `dataset_ref`/`regime` that fail the resolver are rejected (`dangling_context_ref`); valid refs admitted; unknown context dimensions rejected (closed set).
4. **Never-evidence structural test** — no ladder/validation/evidence fields on either artifact (field-level check), admission-only verdict vocabulary, advisory-only assumption status.
5. **Fail-closed schema contract** — empty batch, duplicate refs, unresolved assumption refs, invalid source_ref, empty statement, claim-type cap, self-supersession (content-identity aware), error-collection-in-class, `TypeError` on non-draft, structured-error tuples.
6. **Purity** — static no-import check (no persistence/events/intents reachable), `validate_extraction` never raises for any draft.

## Decisions

- **Scope boundary honored:** no persistence, no events, no intents, no pipeline, no scheduler. The substrate changes no runtime behavior — it is a new deterministic library with fixtures, exactly the manual-proof-first shape.
- **Identity discipline:** one canonical derivation; `content_hash` equals the identity (same rule as EC-V6-20). Batch refs and provenance are excluded from identity so identical assertions dedup across batches (PA4 semantics) while provenance stays traceable on the artifact.
- **Dereference is injected, not hard-wired:** the validator accepts a `context_resolver` stub at substrate level; the real resolver over DatasetManifest / the regime axis arrives with the P7 write path (deferred). Without a resolver, dereference dimensions are checked for form only — a documented boundary, not a bypass (the write path always supplies the resolver, per v6 §29.3).
- **Never-evidence made structural:** neither artifact carries a ladder/validation surface, so a future integration error cannot silently promote a corpus claim (CT-R2 enforced at the type level).

### Running the test suite — three supported ways

All three run the same suite on Python 3.14. CI pins both the `.venv` flow
and the dedicated runner on every commit (the `local-gate` job), and that
job ALSO enforces the strict type + lint gates (`uvx pyright src` and
`uvx ruff check src tests` — mirroring the dedicated `typecheck`/`lint`
jobs without duplicating them), so a drift in any of them breaks CI before
it reaches a developer machine.

1. **Standard project venv** (outside the Hermes desktop app):
   ```bash
   .venv/Scripts/python.exe -m pytest -v
   ```
2. **Isolated runner** (inside the Hermes desktop app — scrubs the host
   venv's broken `hypothesis` plugin from `sys.path`):
   ```bash
   .venv/Scripts/python.exe scripts/run_tests.py -v
   ```
3. **Dedicated 3.14 gate** — sidesteps a stale/broken project `.venv`
   (e.g. one left on 3.11, or one whose `uv sync` fails with a locked
   dist-info). Builds and reuses a gitignored `.venv-py314`:
   ```bash
   scripts/test_py314.sh -v
   ```
   Rebuilding the standard project `.venv` on 3.14 is `uv venv --python 3.14`
   then `uv sync` (the two commands at the top of this section).

The profiled typecheck gate is reproducible locally in ONE command —
`scripts/profiled_gate.sh` runs pyright with the tests profile
(`pyrightconfig.tests.json`, src + tests) followed by the walking-skeleton
smoke, the exact pair the CI `typecheck` + `local-gate` jobs enforce. CI
executes the script itself (`profiled-gate` job), so a drift in either
gate breaks CI before it reaches a developer machine.

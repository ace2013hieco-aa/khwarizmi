**Ownership rule:** `research_sources.py` keeps the ratified Protocol and hosts the new types (§2); the provider machinery lives in `providers/`; nothing here touches `repositories.py`, the gateway, or any DB table — the slice is **read-only by construction** (PA4 `READ_ONLY`, outbox-exempt) and hands `SearchOutcome`/`FetchOutcome` to the task, which routes through the ordinary write path.

**Only-entry-point invariant (PS-03):** the Tool Runtime owns the only `Transport` implementation, and the only entry points into the provider machinery are the runtime's `walk()` and `fetch_batch()`. The provider package is not importable/instantiable outside the runtime context — the same shape as the T4-only rule for generated code. A task or kernel (PA1) that hand-rolls an HTTP call to a provider endpoint is a structural violation, not a performance choice: this invariant is what makes the limiter, the hazard evaluator, the redaction recorder, and the future budget ledger (AR-02) unbypassable.

## 2. Port types and error taxonomy (`research_sources.py`)

### 2.1 Types (dataclasses, deterministic)

```python
@dataclass(frozen=True)
class SearchResult:

    provider: str
    endpoint: str
    query: str                           # exact normalized request sent

    delivered_count: int                 # PS2-05 — post-dedup records delivered to the stream

    total_is_estimate: bool

    content_hash: str

    retrieved_from: str

    raw_bytes_ref: str                   # content-addressed store ref (S12 manifest for large corpora)

class SearchOutcome:

    aggregate: Literal["COMPLETE", "PARTIAL", "EMPTY", "UNAVAILABLE"]   # PS-13
    notes: tuple[str, ...]               # walk notes: STOPPED_AT_LIMIT, dedup, MALFORMED_ROW,
                                        #   total_not_reported…
    request_log: RequestLogRecord | None  # the walk's redacted request log — carried, then
                                          #   persisted by the task at admission (PS-01, §5.2/§8)

@dataclass(frozen=True)
class FetchedSource:                     # PS-01 — per-source fetch outcome
    source: SearchResult

                                         #   any verdict that is a real failure lands in FetchFailure

@dataclass(frozen=True)

    source: SearchResult                 #   but no accessible full text exists (EuropePMC's clean 404
    no_full_text_kind: Literal["NOT_OA", "REMOVED_OR_RETRACTED", "NOT_FOUND"]   # PS3-03 — the
                                         #   driver asserts ONLY what the response evidences (status
                                         #   code + spec-declared markers), never guesses why: a 404
                                         #   alone cannot distinguish "not OA" from "withdrawn"
    evidence_basis: dict[str, str]       # PS3-03 — {status_code, marker_path, provider_spec_version};
                                         #   a provider-declared `retraction_marker` hit maps to
                                         #   REMOVED_OR_RETRACTED, never NOT_OA. Carried in the
                                         #   outcome, counted as COMPLETE, never FAILED.

class FetchOutcome:                      # PS-01 — the fetch driver's aggregate
    per_source: tuple[FetchedSource, ...]
```

Frozen dataclasses throughout — the walk never mutates a record after creation (hash discipline, §16.1-style immutability).

### 2.2 Errors (the §15 taxonomy, typed)

```python
class ProviderError(Exception):          # base; carries provider_id + hazard_class + recordable
class TransientProviderError(ProviderError):      # 429/THROTTLED/5xx/timeouts → retryable
class PermanentProviderError(ProviderError):      # MALFORMED_200/REWRITE_SUSPECT/CURSOR_TRAP/PARTIAL_CONTENT
class RetrievalShortfallError(PermanentProviderError):   # expected, got, cause_class, aggregate
class ProviderUnavailableError(ProviderError):    # aggregate=UNAVAILABLE — could not search (PS-13)
class ProviderValidationError(PermanentProviderError):   # bad hint / bad identifier — before I/O
class RedactionError(ProviderError):     # fail-closed: redaction could not run → no request is issued
```

**Mapping (contract §5.2):** `THROTTLED` → `TransientProviderError`; `MALFORMED_200`/`REWRITE_SUSPECT`/`CURSOR_TRAP`/`PARTIAL_CONTENT`/validation → `PermanentProviderError`; `VALID_NEGATIVE` → **not an error** (a `SearchResult` with `valid_negative: true` + `valid_negative_for` — the identifier that resolved to "no" — PS-11). `EMPTY` aggregate (**searched, found nothing**) → `RetrievalShortfallError(aggregate="EMPTY")`. `UNAVAILABLE` aggregate (**every routed provider throttled/errored/unreachable — the search could not run**) → `ProviderUnavailableError(aggregate="UNAVAILABLE")`, deliberately distinct from `EMPTY` so "no literature exists" can never be concluded from "providers were down" (PS-13). `PARTIAL` aggregate → returned with `aggregate="PARTIAL"` — recorded, not raised (contract §4.2).

## 3. The adapter skeleton (`base.py` + `adapters/*`)

The core design decision: **the walk driver is provider-agnostic; adapters are thin declarative hooks.** This is the Hermes-owned generalization of the upstream `paginate.py` pattern (generic walk + per-provider `api.parse`).

```python
@dataclass(frozen=True)
class ProviderContractCard:
    provider_id: str
    base_url: str
    auth_policy: Literal["none", "query", "header"]     # credentials NEVER in logs (contract §7)
    hint_routes: dict[str, str]                          # identifier_kind -> endpoint selector
    pagination: dict                                    # {kind: cursor|offset|none, start_param,
                                                        #  page_size_cap, max_pages, loop_guard}
    hazard_spec_version: str
    rate_profile: RateProfile                            # {rps, burst, concurrency, daily_cap}
    retry_class_map: dict[str, str]                      # failure class -> transient|permanent

class ProviderAdapter(ABC):
    contract: ProviderContractCard

    # --- the hooks the walk/fetch drivers call ---
    @abstractmethod
    def build_request(self, hints: RetrievalHints, state: PageState,
                      page_size: int) -> RequestSpec: ...
        # RequestSpec {url, params, headers_meta} — passed through redaction (§6) before
        # it may be logged; the credential (if any) is injected here and ONLY here.

    @abstractmethod
    def parse_page(self, payload: ProviderPayload, state: PageState) -> Page: ...
        # Page {records: list[RawRecord], total: int | None, next_state: PageState | None, notes}
        # records are RAW provider rows — raw by construction (PS-12); canonicalization is the
        # extract_ids hook's job, called by the driver immediately per row.

    @abstractmethod
    def extract_ids(self, record: RawRecord) -> dict[str, str]: ...
        # canonical identifiers via normalize_identifier (contract §3.1) — PART of the parse
        # contract (PS-12): the only place identifier canonicalization happens, called once
        # per row by the driver, never deferred.

    @abstractmethod
    def build_fetch_request(self, source: SearchResult) -> RequestSpec: ...
        # fetch-level hook (PS-01) — same RequestSpec/redaction contract as build_request;
        # the PMC full-text fetch path is the canonical case (§5.3).

    @abstractmethod
    def validate_fetch(self, source: SearchResult, payload: object) -> None: ...
        # FD-01 — the FIFTH hook: content-validation on the artifact verdicts
        # (NONE / INJECTION_SUSPECT) BEFORE artifact construction. Raises
        # FetchContentRejected(reason) on non-full-text shapes (junk HTML, <error>-rooted
        # wrappers, HTML-when-PDF-promised). The driver maps a rejection to
        # FetchFailure(EMPTY_RESULT, reason=<hook message>) — never a FetchedSource. The
        # thin-adapter rule still holds: no retry/rate-limit/reconciliation logic here —
        # only the provider-shaped content test.
```

**The eleven adapters** each declare a `ProviderContractCard` (the §3 table of the contract, one card per row) and implement the five hooks (build_request, parse_page, extract_ids, build_fetch_request, validate_fetch — FD-01). Nothing else: **no rate-limit logic, no retry logic, no reconciliation logic, no logging, no redaction, no cursor bookkeeping in the adapter.** All of that lives in the driver/limiter/recorder. An adapter is ~80–150 lines of declaration + parsing — the thin-adapter shape §15 mandates.

**Registration:** `adapters/__init__.py` exposes `PROVIDER_REGISTRY: dict[str, type[ProviderAdapter]]`. The allowlist is enforced at the registry boundary: `get_adapter(provider_id)` raises `ProviderValidationError` for a provider outside the ratified §27 item 55 allowlist. Registry membership == allowlist membership; new providers require an engineering-plane change (§3 of the contract).

## 4. The hazard-spec evaluator (`hazards.py`)

### 4.1 Spec schema (machine-readable, versioned, part of the SkillRecord content)

```python
@dataclass(frozen=True)
class ProviderHazardSpec:
    provider_id: str
    version: str                          # "1.0.0" — recorded on every SearchResult.provenance
    markers: tuple[HazardMarker, ...]     # {field_path, equals | pattern, failure_class}
    empty_body_rule: Literal["treat-as-failure", "valid-negative"]
    error_field: ErrorFieldSpec | None    # {name, code_pattern}
    count_semantics: Literal["exact", "estimate", "absent"]
    counts_raw_rows: bool                 # PS-04: True = total counts EVERY raw row incl. repeats
                                          #   (Crossref) → dedup BEFORE comparing; False = total is
                                          #   dedup-truthful → compare raw retrieved counts. The
                                          #   dedup-direction is spec content, never a driver guess.
    required_fields: tuple[str, ...]      # PS-08 schema-drift sentinel: absence of any required
                                          #   field → MALFORMED_200 (fail closed, never silent
                                          #   degrade into empty identifiers/abstracts)
    cursor_rule: CursorRule                # {kind, loop_guard: max_pages}
    throttle_signature: tuple[ThrottleSig, ...]  # {status: 429?, body_pattern?}
    rewrite_suspect: tuple[RewriteRule, ...]     # silent-filter detection
    fetch: FetchHazardRules | None        # PS2-02 — fetch-scoped rules; None = no fetch surface.
                                          #   The search-shaped fields above do NOT apply to fetch
                                          #   payloads (count_semantics/cursor_rule/rewrite_suspect
                                          #   are meaningless for a JATS full-text response).
```

```python
@dataclass(frozen=True)
class FetchHazardRules:                   # PS2-02 — the fetch-scoped structure
    body_marker: FieldPath | None         # where the body element lives (e.g. "pmc-articleset.body")
    metadata_marker: FieldPath | None     # where the metadata/front element lives ("…front")
    body_required: bool                   # pmc: metadata present AND body absent → PARTIAL_CONTENT —
                                          #   a composite structural check no single field marker
                                          #   can express (the exact PMC case). **PS3-02: a
                                          #   present-but-empty body element counts as absent**
    empty_body_rule: Literal["treat-as-failure"] = "treat-as-failure"   # PS3-02 — a fetch empty
                                          #   body is NEVER a valid negative (the search-shaped
                                          #   `valid-negative` empty rule never applies at fetch scope)
    no_full_text_status: int | None       # europepmc: 404 → NO_FULL_TEXT (a RESULT, never a failure)
    no_full_text_marker: FieldPath | None # optional body-level signal — **PS3-08: when present,
                                          #   marker evidence wins over status alone**
    retraction_marker: FieldPath | None   # PS3-03 — provider-declared retraction/withdrawal signal:
                                          #   a hit maps to NO_FULL_TEXT(REMOVED_OR_RETRACTED), never
                                          #   NOT_OA (a 404 alone cannot distinguish the two)
```

**Spec-loading validation (PS2-09 + PS3-05):** the fail-closed registration check rejects incoherent `count_semantics` × `counts_raw_rows` combinations — `estimate` requires `counts_raw_rows: true` (an estimate that is dedup-truthful is just "exact"); `absent` forbids `counts_raw_rows: true` (moot without a total); `exact` allows either but `false` is the norm. A spec that violates the matrix fails registration, never ships a contradiction the driver must interpret. **The same discipline extends to `FetchHazardRules` (PS3-05):** registration rejects (a) `body_required: true` without a `body_marker`; (b) any fetch rule on a spec whose provider has no fetch surface; (c) `no_full_text_marker` without `no_full_text_status`; (d) a `FetchHazardRules` with neither `body_required` nor `no_full_text_status` nor fetch-scoped `required_fields` — a fetch rule set that can never fire fails registration.

Loaded from `hazard_specs/<provider>.json` at adapter registration, validated against the schema (fail-closed: an invalid spec is a startup/registration error, never a runtime skip). Spec files are **content** — they change through the engineering plane with version bumps, never at runtime.

### 4.2 `evaluate_hazards` — one deterministic evaluator

```python
def evaluate_hazards(provider: str, spec: ProviderHazardSpec,
                     payload: ProviderPayload, context: HazardContext) -> HazardVerdict:
    # HazardVerdict {class: NONE|MALFORMED_200|EMPTY_RESULT|PARTIAL_CONTENT|THROTTLED|
    #                REWRITE_SUSPECT|CURSOR_TRAP|INJECTION_SUSPECT|VALID_NEGATIVE|NO_FULL_TEXT,
    #                reason, detected_by, recordable}
```

Evaluation order (fixed, deterministic):

1. **Status check** — non-200/2xx → map (404 → `VALID_NEGATIVE` for identifier lookups per the provider's spec; 429 → `THROTTLED`; 5xx → transient). **Fetch-scope precedence (PS3-01):** when `HazardContext.scope` (set by the driver — never payload-inferred) is `FETCH`, the 404 branch is **short-circuited** by the fetch-scoped `no_full_text_status`/`no_full_text_marker` mapping of step 6a — a fetch 404 is `NO_FULL_TEXT`, never `VALID_NEGATIVE`; `VALID_NEGATIVE` is unreachable at fetch scope.
2. **Throttle signature** — status 429, or body-only signatures (arXiv plain-text `Rate exceeded.`) → `THROTTLED`.
3. **Markers** — each `HazardMarker` predicate over the payload (e.g. arXiv entry title == "Error"; EuropePMC `errCode` field pattern) → declared class. First hit wins in spec order.
3a. **Required fields (PS-08)** — any `required_fields` key absent from the payload → `MALFORMED_200` (the schema-drift sentinel: a provider field rename fails closed instead of degrading silently into empty identifiers/abstracts).
4. **Empty-body rule** — empty body → `EMPTY_RESULT` or `VALID_NEGATIVE` per the spec's `empty_body_rule`.
5. **Rewrite rules** — declared-filter-vs-response consistency (OpenAlex silent filter drop) → `REWRITE_SUSPECT` with expected-vs-got counts.
6. **Injection heuristic** — instruction-like markers in text fields → `INJECTION_SUSPECT` (**flag only**, advisory; never a block — contract §5.4).
6a. **Fetch scope (PS2-02/PS3-01/PS3-02/PS3-03/PS3-08)** — only when the spec declares `fetch` rules and the payload is a fetch response (the `HazardContext.scope` flag, driver-set — never payload-inferred, PS3-01): `no_full_text_status` match (europepmc 404) → `NO_FULL_TEXT` (a result, never an error) — **marker evidence (`no_full_text_marker`) wins over status alone when present (PS3-08)**; a `retraction_marker` hit → `NO_FULL_TEXT(REMOVED_OR_RETRACTED)`, never `NOT_OA` (PS3-03); `body_required` with `metadata_marker` present and `body_marker` absent-or-empty → `PARTIAL_CONTENT` (the composite PMC check, present-but-empty == absent, PS3-02); fetch `required_fields` absence → `MALFORMED_200` — **which dominates `PARTIAL_CONTENT` when both would fire (PS3-08)**; a fetch response with no body content and no matching verdict → `EMPTY_RESULT` via the fetch `empty_body_rule` — **never a fall-through to `FetchedSource` (PS3-02)**. The basis of every fetch verdict (status, marker path) is recorded in `detected_by`.
7. **Cursor trap** — detected by the walk driver (§5), reported into the verdict for recording.

The evaluator is **generic** — it reads the spec, it contains no per-provider branches. The per-provider knowledge lives in `hazard_specs/*.json`, and the catalog entries (contract §5.3) are the fixtures that prove the evaluator.

## 5. The reconciliation walk (`paginate.py`)

### 5.1 The driver

```python
def walk(adapter: ProviderAdapter, hints: RetrievalHints, request: WalkRequest,
         transport: Transport, limiter: ProviderRateLimiter,
         recorder: RequestRecorder, clock: Clock) -> SearchOutcome:
    # WalkRequest {max_results, max_pages, page_size_cap, retry_policy}
```

Fixed algorithm:

1. **Hints → route** — `parse_query_hints(query)`; if the query has no provider-resolvable hint and the adapter has no topic surface, the walk is skipped (the routing layer fans out to the topic-capable subset **in the fixed allowlist order of §3 — never dict/arrival order (PS-05)**; walk concurrency is a latency choice, aggregation is always serialized in that fixed order). **Routing corners (PS3-06):** an unknown hint prefix (`xyz:…`) is `ProviderValidationError` before any I/O; a query routeable to **no** adapter at all (every routed adapter skipped) aggregates `UNAVAILABLE` — the walk ran no provider and must never read as "searched, found nothing." **Walk mode (WS-01):** the driver derives a `lookup`/`query` mode from the parsed hints — an identifier hint (`doi:`/`pmid:`/`pmcid:`/`arxiv:`/`url:`) → `lookup`; a topic hint → `query` — because the `VALID_NEGATIVE` resolution rules (§4.2 (c)/(d)) apply **only in `lookup` mode**.
2. **Page loop** — for each page: limiter.acquire(provider) → build_request → **redact at the recorder boundary** (the only place a request form is created; contract §7.2) → transport.request → **hazard evaluate** on the raw payload → **parse_page** → accumulate. `Retry-After` honored for `THROTTLED`; jittered exponential backoff ≤ `max_retries` for transient class only; permanent class raises immediately. **Mid-walk failure rule (WS-04):** any page failure after ≥ 1 successful page — transient-after-retries OR permanent-immediate — converts to the provider's `SHORTFALL(cause=<failure class>)` with the accumulated records returned flagged; **only a FIRST-page failure with zero delivery feeds the zero-delivered matrix** (§4.2).
3. **Bounds (contract §4.4)** — `page_size_cap`, `max_pages`, `max_records` enforced by the driver **against `min(spec.cursor_rule.loop_guard, request.max_pages)` (WS-03): hitting the SPEC guard while a live cursor remains is `SHORTFALL(cause=CURSOR_TRAP)` — the spec's guard IS the trap threshold; hitting a REQUEST bound records `STOPPED_AT_LIMIT`** (a note; `COMPLETE`-with-note, never a `SHORTFALL`).
4. **Cursor guard** — **BEFORE issuing page N+1 the driver checks the seen cursor-chain: a `next_cursor` (or offset) already seen stops the walk WITHOUT issuing the duplicate request (WS-06)**; a repeating `next_cursor`/non-advancing offset → `CURSOR_TRAP` → stop, `SHORTFALL(cause=CURSOR_TRAP)`.
5. **Canonicalize + dedup** — each record → identifiers via `extract_ids` (called immediately per row — the only canonicalization home, PS-12) → cross-provider dedup key (doi → pmid → pmcid → arxiv, first-seen wins; duplicates recorded in notes, never silently dropped). **Row-level policy (PS-07):** a malformed row is **skipped-and-counted** with a `MALFORMED_ROW` note — it never aborts the walk and never silently vanishes; a page that is structurally unparseable (schema violation) is a page failure, not a row skip.
6. **Reconciliation verdict per provider** (§4.1 of the contract): `COMPLETE` (walk exhausted naturally / bounded-by-request reached) | `SHORTFALL` (premature termination: broken cursor chain, mid-walk page failure — transient-after-retries OR permanent-immediate, WS-04, `total > raw_retrieved` with no next page, `total > 0` with zero delivered, an empty page mid-walk (`EMPTY_MID_WALK`), or a `VALID_NEGATIVE` page in a query-mode walk (`VALID_NEGATIVE_MID_WALK`)) | `UNKNOWN` (no total, not exhaustible — `total_is_estimate: true`, noted). **Exhaustion rule (WS-02):** "exhausted naturally" is cursor-aware AND position-aware — an empty page WITH a live next cursor CONTINUES the walk (up to bounds); an empty page after ≥ 1 non-empty page is `SHORTFALL(cause=EMPTY_MID_WALK)`; "exhausted" means (empty page ∧ no next cursor ∧ first page) ∨ (no next cursor after a non-empty page). **Count comparison (PS-04/PS2-05):** the reconciliation reads **`raw_retrieved_count`** — pre-dedup rows — for the bound-reached `COMPLETE` check and for the `counts_raw_rows: false` comparison; the **`delivered_count`** (post-dedup stream) is never used in a reconciliation decision. `counts_raw_rows: true` (Crossref) dedups by DOI before comparing; the dedup-direction is per-provider spec content, never a driver guess — a dedup-heavy walk that reached its bound is `COMPLETE`, never a false `SHORTFALL`.
7. **Aggregate** (§4.2 — the full matrix, PS2-03 + PS3-06): (a) ≥ 1 provider delivered a real result → `PARTIAL` if any other provider `SHORTFALL`/`UNKNOWN`, else `COMPLETE`; (b) **zero real results delivered** — `EMPTY` (**searched, found nothing**) → `RetrievalShortfallError(aggregate="EMPTY")` if ≥ 1 provider *searched* (its zero/valid-negative causes and any down providers recorded in notes), `UNAVAILABLE` (**could not search**) → `ProviderUnavailableError(aggregate="UNAVAILABLE")` only if **no** provider searched (incl. the routeable-to-no-adapter case, step 1); (c) a **valid-negative-only** identifier lookup (≥ 1 provider answered "no" — `valid_negative: true` + `valid_negative_for`) → `COMPLETE` (answered), with down/unrun providers recorded in notes — never `PARTIAL`, never `EMPTY`; (d) **valid-negative mixes (PS3-06)** — a valid-negative answer mixed with an empty topic search, or with real results, is `COMPLETE` (the lookup was answered) with the other causes in notes — never `PARTIAL`, never `EMPTY`. **Mode gate (WS-01):** rules (c)/(d) apply ONLY in `lookup` mode (step 1) — a `query`-mode walk is never "answered" by a valid negative; a query-mode `VALID_NEGATIVE` page is a mid-walk anomaly (`SHORTFALL`, step 6). **Ran vs searched (WS-07):** "searched" = ≥ 1 response parsed (any hazard verdict); "ran" = the transport was called; `EMPTY` requires ≥ 1 provider *searched* with zero delivered; `UNAVAILABLE` requires zero *searched*. **Reading rule (WS-05 — the walk's PS3-04 analog):** the aggregate is a *resolution* signal, never a coverage claim — `COMPLETE` means "every routed provider resolved", which includes `STOPPED_AT_LIMIT` (bounded-by-request) and `UNKNOWN` (no total); any coverage conclusion must read the per-provider reconciliations + notes. The matrix is the contract's; the driver implements it.
8. **Record** — every page's request (redacted), cursor_key, counts, hazard verdicts, and the final reconciliation go to the `RequestLogRecord` (§8 of the contract) — re-runnable, deterministic. **Driver-injected verdicts (WS-06):** the evaluator never emits `CURSOR_TRAP` (driver-detected) — the driver injects the detected trap into the page's `hazard_verdicts` here so the log stays complete.
9. **Fetch is a separate driver (PS-01)** — `fetch_batch()` (§5.3) runs the same limiter → redact → transport → hazard pipeline per source with its own `FetchOutcome`; search and fetch are never fused, so a fetch-level hazard (PMC metadata-only-no-body) can never be silently admitted as full text.

## 6. Rate limiter and redaction (design details)

### 6.1 `ProviderRateLimiter` (`ratelimit.py`)

```python
class ProviderRateLimiter:
    def __init__(self, profiles: dict[str, RateProfile], clock: Clock): ...
    def acquire(self, provider: str) -> tuple[bool, str]: ...  # RL-01 (fourth gate): the DECISION
    #                                           # and the CAUSE return under one lock —
    #                                           # (True, "") | (False, "daily_cap_exhausted")
    #                                           # | (False, "admission_wait_expired"); blocking
    #                                           # (bounded) for bucket+semaphore; a denial is
    #                                           # WITHOUT blocking on a hard policy stop
    #                                           # (daily cap) — NEVER raises, NEVER hangs
    def release(self, provider: str) -> None: ...
    def note_throttled(self, provider: str, retry_after: float | None) -> None: ...  # shapes FUTURE
    #                                           # acquires only — never sleeps the caller
    def last_denial_reason(self, provider: str) -> str: ...  # RT3-03: "" | "daily_cap_exhausted"
    #                                           # | "admission_wait_expired" — DIAGNOSTIC-only
    #                                           # (the driver branches on the atomic reason)
```

- **Per-provider token bucket** (rps, burst) + **per-provider semaphore** (concurrency) + **global bounded concurrency**; FIFO (the waiter queue), no per-task fair-share claim (RT-04 — task-level cost is the future budget ledger's job, §6.4; `acquire(provider)` carries no task handle and the claim was unimplementable).
- **Policy-exception contract (RT-01/RT2-02/RT3-02/03/RL-01):** `acquire` NEVER raises out of the limiter for a policy condition and NEVER blocks on a hard stop, and the DECISION + CAUSE return atomically — `(True, "")` | `(False, "daily_cap_exhausted")` | `(False, "admission_wait_expired")` under one lock (RL-01, fourth gate — a caller can never read ANOTHER caller's denial through a separate accessor; `last_denial_reason` is diagnostic-only). **`False` is reserved for the daily cap** (a hard stop — the cap will not clear within the retry window, so **no retry**). The admission waits are bounded by construction — the token bucket's wait is ≤ the burst-refill time (a token arrives within 1/rps) and the semaphore/global-concurrency wait is short because the driver releases per request — with a named `ADMISSION_WAIT_BOUND` (default 60s) as the safety net. **The causes differ in RETRY semantics (RT3-02): the daily cap is a hard stop — the driver returns the THROTTLED failure path with NO retry; the admission-wait expiry is TRANSIENT contention — the driver backs off and RETRIES the page (the next acquire may succeed; the per-request release pattern frees the slot).** The cause note (`daily_cap_exhausted=true` / `admission_wait_expired=true`) is appended to the outcome's notes from the atomic reason. **The daily cap is a hard stop even under queued waiters (CAP-01, fourth gate):** the top-of-acquire check is the no-wait fast path AND the wait loop RE-CHECKS the cap before the grant condition — a waiter queued while `cap_used < cap` can never grant after other waiters exhausted the cap; it is removed from the FIFO queue and denied with the no-retry `daily_cap_exhausted` label (never `admission_wait_expired`). A raise from `acquire` would escape `_fetch_page`'s try and violate `walk()`'s never-raises invariant — structurally impossible under this contract.
- **Release contract (RT-03/RT2-03):** `release` returns the **semaphore slot ONLY** — a token is never refunded (a refund would hollow the rps/burst bucket under the driver's per-request acquire/release; a walk could loop at burst speed). The driver's per-request acquire→request→release (WK3-01) is correct as the semaphore/global-concurrency gate; the token bucket is charge-only. **Code shape (RT2-03/RT3-02/RL-01):** the return check happens BEFORE the try — `granted, reason = limiter.acquire(...); if not granted: if reason == "daily_cap_exhausted": return None, "THROTTLED", "THROTTLED", reason` (hard stop, no retry, no release — a `False` never reaches the `finally: release`, which would underflow the semaphore and admit MORE than `concurrency`); `admission_wait_expired` → backoff and continue the attempt loop (retryable). The denial reason is returned to the walk loop (a small `_fetch_page` signature addition), which appends the cause note. The step-5a fetch driver inherits the same contract: `False` → `FetchFailure(THROTTLED)` (RT2-05), never an unhandled tuple.
- **Retry-After honored (RT-08):** a `THROTTLED` response's backoff is **shaped by the bucket for FUTURE acquires only** — the bucket refills at rps, so subsequent `acquire`s wait for tokens; the limiter NEVER sleeps the current caller. The driver's `_backoff` (clock.sleep, exponential + jitter) is the ONLY caller-sleeping backoff — no double-delay.
- **Daily cap (RT-10):** a **fixed UTC window** — midnight per `clock.now_utc`'s date; a hard stop returns `False` (above); recorded in the request log + `search_accounting`.
- **Profile validation (RT-09):** fail-closed at **construction** — `rps > 0`, `burst >= 1`, `concurrency >= 1`, `daily_cap > 0`, else `ValueError` (a hollow/dead profile is a config error, never a silent default). The §6.2 operator-config validation remains at P7; construction validation is step 4.
- **Clock-injected** — tests drive it with `frozen_clock`; determinism without sleeping.
- **Wraps-vs-gate (RT-07):** the limiter is a **separate gate in front of the transport at the driver call site — it does NOT wrap the transport.** The driver (`_fetch_page`) holds the RAW transport and calls acquire → request → release; `transport.request` appears in exactly one place (the driver), which is the only-entry-point invariant (PS-03) made structural — no component other than the driver may call the transport, and the limiter never sees the transport (no double-limit risk, no bypass). Single instance owned by the Tool Runtime; concurrent walks are permitted (latency) but **aggregation is always serialized in the fixed §3 allowlist order** (PS-05).

### 6.1a `http.py` — the single HTTP client (S11 defaults, RT-02/05/06)

```python
class ProviderHTTPTransport:   # implements the Transport protocol
    def __init__(self, redaction: RedactionPolicy, timeouts: ..., size_caps: ..., ...): ...
    def request(self, spec: RequestSpec) -> TransportResponse: ...
```

- **Exception class map (RT-02/RT2-01/RT2-06/TR-01):** `http.py` raises ONLY `ProviderError` subclasses with a named `hazard_class` **for TRANSPORT-LEVEL failures** (timeout/connection → `TransientProviderError(hazard_class="TIMEOUT")`, retryable per §6.3; size cap → `PARTIAL_CONTENT`), with the redaction-`from None` discipline (PS-02/PS2-04/PS3-07). **The map covers the BODY-READ phase as well as `urlopen` (TR-01, fourth gate):** a mid-download read timeout / connection reset / `IncompleteRead` — on the success AND the HTTPError paths — maps to `TransientProviderError(TIMEOUT)` and can never escape bare (which would crash the walk via the RT2-06 re-raise); the size-abort `PermanentProviderError` passes through untouched. **ALL HTTP statuses are deferred to `evaluate_hazards` — the transport NEVER raises on a status code** (RT2-01): raising on 404 would kill the answered-lookup `VALID_NEGATIVE` (WS-01) and raising on 429 would bypass `note_throttled`/Retry-After; the evaluator is the single status classifier (THROTTLED/VALID_NEGATIVE/MALFORMED_200/…). A bare `socket.timeout`/HTTP-client exception is NEVER propagated. **Catch-all (RT2-06):** a NON-`ProviderError` exception from the transport is a bug — `_fetch_page`'s generic `except Exception` RE-RAISES it (loud, never a schema verdict); only `ProviderError` subclasses are mapped to hazard classes.
- **Size caps (RT-06/RT3-01):** S11 bounded downloads apply to BOTH fetch and the walk's search pages; `WalkRequest` gains `size_cap_bytes` (the S11 scale class). **The rule is SPLIT (RT3-01):** (a) the streaming download-abort is genuinely transport-level — it fires ONLY when the status is 2xx (a throttled or error response keeps its status verdict — status evidence dominates; an oversized 429 is THROTTLED, never `PARTIAL_CONTENT`) and raises `PARTIAL_CONTENT` (a permanent class, never silent truncation); (b) the completed-body size check moves into the **evaluator** — the body length travels in `HazardContext` and the check runs after the status verdicts (an oversized COMPLETE 2xx body → `PARTIAL_CONTENT`). The fetch path already carries `size_cap_bytes` per artifact.
- **Content-type check (RT-05/RT2-04/RT3-04):** the check lives in the **hazard evaluator**, not the transport — `TransportResponse` gains `content_type` and `HazardContext` carries it, so the per-provider `content_types` allowlist (arXiv: `application/atom+xml`, PMC: `text/xml`/NXML — never a blanket JSON-only check) is consulted inside `evaluate_hazards`' fixed evaluation order. **Slot pinned (RT3-04):** after the status verdicts (THROTTLED/VALID_NEGATIVE — status evidence dominates, the FS-03/04 principle), the required-fields drift sentinel, and the empty-body rule, and BEFORE the fetch-scoped step 6a composites — so shape evidence (drift/empty) and content evidence (retraction/`NO_FULL_TEXT`) both dominate the label check, and only a 200-with-parseable-body-and-mismatched-label reaches it. A declared allowlist + mismatch (at the pinned slot) → `MALFORMED_200` (permanent); without an allowlist the mismatch is a note and the `required_fields` drift sentinel is the shape-aware backstop.

**Step-4 implementation edits (RT3-05 — the shipped interfaces this text changes):** `base.py` — `ProviderRateLimiter.acquire -> bool`, add `last_denial_reason(provider) -> str`, add `TransportResponse.content_type: str | None`, add `WalkRequest.size_cap_bytes`; `hazards.py` — `HazardContext` gains `content_type` and `body_size`, the evaluator gains the content-type + completed-body-size checks at the pinned slots; `paginate.py` — `_fetch_page` checks the `acquire` return BEFORE the try (cap → no-retry return; admission expiry → backoff + retry), returns the denial reason for the walk loop's cause note, and the catch-all re-raises non-`ProviderError` exceptions; `tests/test_provider_walk.py` — `FakeLimiter` gains the new methods and a scriptable `acquire` return.

### 6.2 Redaction (`redact.py`)

```python
@dataclass(frozen=True)
class RedactionPolicy:
    credential_aliases: frozenset[str]     # api_key, apikey, key, token, access_token, auth, password, secret, signature…
    polite_identifiers: frozenset[str]     # email, tool — SENT on the wire, REDACTED in every record
    default_deny: bool = True              # unknown param name → redacted + policy_gap note

def redact_url(url: str, policy: RedactionPolicy) -> str: ...
def redact_params(params: dict[str, str], policy: RedactionPolicy) -> dict[str, str]: ...
def redact_headers(headers: dict[str, str], policy: RedactionPolicy) -> dict[str, str]: ...  # PS-09
```

- Applied **once, at the recorder boundary** — before logging, provenance, events (S6 validator as write-path backstop), or error messages. A `RedactionError` fail-closes the request before it is issued if redaction cannot run.
- Credential aliases → `"<redacted>"`; polite identifiers → `"<redacted:email>"`/`"<redacted:tool>"` (sent, never stored); unknown names → redacted + `redaction_policy_gap` note. **Headers (PS-09):** `redact_headers` covers `Authorization`, cookies, and any credential-class header — `RequestSpec.headers_meta` is recorded only in redacted form, so a `header`-auth adapter's credential never reaches a record.
- **Exception-path rule (PS-02, structured PS2-04, completed PS3-07):** the transport is **constructed with the `RedactionPolicy`** and is the **only component that raises provider errors** — it builds every exception message from the policy-redacted request form (`<redacted>` placeholders) and raises `from None`, attaching no original exception (whose `__cause__`/`__context__`/traceback could carry the raw URL). **Hop-level discipline (PS3-07):** the `from None` rule holds at **every re-raise hop** — concurrent future wrappers and `ExceptionGroup` machinery re-raise with captured tracebacks, and a generic `raise exc` anywhere in the chain re-links it, so every hop must re-raise `from None` (the transport's `__suppress_context__` must survive each hop). **`RedactionError`** — raised while raw credentials are in scope — names the offending parameter, **never its value**. `redact_url` applies the alias scan to **path segments** too, not only query params (a credential in a `/{token}/…` route must be masked). A `ConnectionError`/`HTTPError`/timeout therefore cannot leak a query-auth credential or a polite-pool `email` into task output/events; this closes the leak *before* the S6 write-path validator ever sees it (S6 remains the backstop).
- Tests prove a real key value appears in **zero** records and **zero** exception messages (contract §7.3 / §9 row 23).

## 8. Handoff and non-goals

- **Handoff:** `walk()` returns `SearchOutcome` and `fetch_batch()` returns `FetchOutcome` to the calling task; the task routes `Source` records + `SourceArtifact`s through the ordinary write path (existing gateway/admission), persists the carried redacted `RequestLogRecord`/`FetchLogEntry` facts into the `Source` provenance atomically with admission (PS-01/PS2-07 — no new table, dereference contract per §5.3), and records `search_accounting` (incl. `PARTIAL`/`EMPTY`/`UNAVAILABLE` aggregates, `NoFullText` counts, and fetch failures) on the `LiteratureReview` — this slice never writes.
- **Non-goals (explicitly deferred):** live network in CI (opt-in P7 smoke only); providers beyond the 11-provider allowlist; the web-search adapters (Serper/Searxng — separate row of item 55); full-text extraction beyond JATS/Atom; budget-ledger integration (AR-02, DEFERRED — the limiter is provider policy only, §6.4 of the contract); LitKG/GraphRetrieval integration (GR1/GR2 phases); the `EXTRACT`/claim pipeline (already implemented, consumes this slice's `Source` output).
- **What this slice deliberately does NOT do:** no DB tables, no events, no intents, no gateway changes, no SkillRecord admission (PA3 is a separate precondition, §27 item 56), no ratification claim.
